## 1. 项目目标

以 scikit-learn 内置葡萄酒数据做三分类：输入是 13 项数值特征，输出是三个类别之一。它适合练习流程，不代表真实生产数据的全部复杂性。交付物包括数据说明、划分规则、基线、候选模型、误差分析和最终报告。

先写清样本含义、特征单位和标签来源；本项目数据量小，保留固定测试集后，训练集内用分层交叉验证选择方案。测试集只在流程确定后使用一次，不能因为结果不好就重新挑选随机种子。

<a id="sec-2"></a>

## 2. 建立评价协议

主要指标使用 macro-F1，使三个类别等权；辅助指标使用准确率与混淆矩阵。基线是多数类分类器。候选方案为标准化逻辑回归与受限深度的随机森林，先少量比较，再根据误差决定是否扩展。

预先写出候选超参数范围，避免在看见测试结果后无限增加尝试。数据较少时，单次划分有较大波动，最终报告应明确这一局限。

<a id="sec-1-1"></a>

### 基础算例：把分类项目验收写在训练之前

先约定样本划分、主要宏 F1、简单基线和最终测试使用次数，再运行搜索。数据读取后核对每类支持数、缺失与重复，并保存划分索引。这样后来看到分数时，能知道它来自什么总体和选择过程。若先试多个划分再保留最高测试结果，即使代码随机种子被保存，也没有消除选择偏差；复现某次高分与证明方案有效不是同一个目标。

<a id="sec-2-1"></a>

### 机制展开：协议先固定选择与最终报告

将开发集交叉验证用于超参数比较，最终测试只评价确定方案。基线与候选共享划分、主要指标和预处理边界，候选搜索成本也要保留。项目开始就写明测试后能否继续修改、修改后如何获得新证据，避免报告中“最终”反复移动。保存划分索引可复现样本，但合法性仍取决于来源、实体和时间定义。

<a id="deep-dive-2"></a>

### 深入讲解：把项目评价协议写成可以被别人执行的约定

项目先固定预测单位、输入列、标签、部署可见范围与错误成本，再划分数据。表格分类示例也应说明每行独立性和类别含义，不能因数据来自内置库就略去协议。

基线只用训练信息，例如多数类或先验概率；候选前处理在训练折拟合。明确主要指标、搜索空间及预算，避免跑完后按最有利指标解释成功。

实验记录每行对应一个假设和一组完整配置，包含数据标识、分割、模型、超参数、选择规则、时间与结果。若同时修改特征和模型，结论应描述完整方案，而非单个模块贡献。

先用小输入检查列顺序、类别映射和概率输出，再正式训练。样本数和特征数只是格式，缺失含义、来源和时间决定是否适合当前预测。

验收让独立进程复现分割与指标，并能说明最主要错误与限制。项目完成不只是一份可运行代码，还包括结果为何可信、在何处可以使用的解释。

<a id="sec-3"></a>

## 3. 实验记录模板

| 字段 | 应记录的内容 |
| --- | --- |
| 数据 | 名称、样本数、类别分布、版本 |
| 划分 | 比例、分层规则、随机种子 |
| 模型 | Pipeline、参数范围、选择指标 |
| 结果 | 验证分数、测试分数、错误样本类型 |
| 成本 | 训练时间、预测时间、依赖版本 |

记录模板应在训练前建立；不能只留下最后一个最好分数。项目成功标准是流程正确且结论有依据，不是达到事先猜测的高分。

<a id="sec-4"></a>

## 4. 写出可判定的项目问题

项目问题可以写成：“在固定分层划分上，标准化逻辑回归的 macro-F1 是否超过多数类基线，并且各类召回是否均有可用水平？”它比“用机器学习分析葡萄酒”更可执行，因为定义了输入输出、比较对象和评价标准。

若后续要加入随机森林，应使用同一训练验证协议，记录完整候选范围，并在最终确定后统一进行测试。由于数据规模有限，结论应定位为教学实验中的观察，而不是关于所有此类问题的算法排名。提前界定结论范围，能避免最后为了单次高分编造宽泛解释。

<a id="sec-5"></a>

## 5. 数据说明要可核查

报告每个类别样本数与划分后数量，确认验证折可包含各类。数据很少时，大范围超参数搜索容易过度适应验证噪声，应优先使用少量有解释的候选。

预先写出失败标准，例如没有超过多数类、某类召回过低或训练时间超预算。项目交付应包括失败分析，而不是只有成功时才有结论。

任务说明应让读者知道每行代表的实体、观察时点、目标窗口和特征何时可用；字典写明单位、缺失含义及来源。若一个实体有多条记录，需解释分组划分与权重，否则统计行数不等于独立样本量。

记录排除规则与每步数量变化，特别是缺失标签、重复键和时间边界。训练、验证和测试的总体差异也应描述，而不仅给一个比例。这样后续的性能分数才能对应清楚的样本范围，并能判断部署数据是否仍符合条件。

<a id="sec-6"></a>

## 6. 进阶：把项目视为可证伪实验

预设主要指标、基线、候选范围与最小有意义差异，能避免见结果后改问题。小数据上的很小分数差异可能只对应一条样本，实验应报告支持度和波动，而不把小数位当稳定发现。

样本划分是任务假设：随机分层近似同来源新样本，按实体或时间则检验不同泛化。项目结论不得超出实际协议。数据、算法和预算的对照设计，比多加几个模型名称更接近研究。

<a id="sec-6-1"></a>

### 项目协议应先锁定样本与决策单位

分类项目开始前先定义目标类别、样本来源、是否含同实体重复观察、主要指标和允许使用的信息。葡萄酒内置数据适合演示流程，却不能支持所有生产来源的泛化结论。若真实任务按酒厂或批次部署，需要相应分组评价。

可把协议写成四个可判定问题：测试对象是什么，训练能看到什么，如何选择候选，最终报告什么。多数类基线、预处理、搜索空间和随机种子都属于方案的一部分；只规定一个模型名称不能约束完整实验。

训练前先核对标签与特征行号、类别数量和重复样本，再进行划分。项目成功标准除了分数，还包括样本统计可对账、数据处理无泄漏、结果可重算和错误类型可解释。先写验收，再写搜索代码，能减少事后根据结果修改目标。

<a id="sec-7"></a>

## 7. 练习与参考答案

**练习：** 如果最终测试集只有几十个样本，某类别少错一条就能明显提高分数，应如何写结论？

**答案：** 报告原始错误数量与类别支持度，说明样本量有限，避免把很小差异称为稳定优势。必要时另外设计重复评估，而不是反复使用原测试集调参。

<a id="sec-7-1"></a>

### 边界追问：先看测试再写主要指标是否公平

**问题：** 试过多个指标后挑候选最领先的一项作为主要结果，是否仍属预先协议？

**推理解析：** 不是，指标本身参与了选择。应提前固定任务代价与主要指标，其他作为补充；探索结果另标并用未参与决策的数据确认。记录所有候选、划分与预算，使结论能对应完整流程，不能只保留最后最好的一张表。
