## 1. 从基线到搜索

下面代码可直接运行，包含训练测试分离、折内标准化和最终报告。仅搜索正则参数，便于理解每一步的作用。

```python
from sklearn.datasets import load_wine
from sklearn.model_selection import train_test_split, StratifiedKFold, GridSearchCV
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.dummy import DummyClassifier
from sklearn.metrics import f1_score, classification_report, confusion_matrix

X, y = load_wine(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=42
)
cv = StratifiedKFold(4, shuffle=True, random_state=42)
baseline = DummyClassifier(strategy="most_frequent").fit(Xtr, ytr)
pipeline = make_pipeline(
    StandardScaler(), LogisticRegression(max_iter=2000)
)
search = GridSearchCV(
    pipeline,
    {"logisticregression__C": [0.01, 0.1, 1., 10.]},
    scoring="f1_macro", cv=cv, refit=True
)
search.fit(Xtr, ytr)
prediction = search.predict(Xte)
print("baseline:", f1_score(yte, baseline.predict(Xte), average="macro"))
print("parameters:", search.best_params_)
print("validation:", search.best_score_)
print(classification_report(yte, prediction, zero_division=0))
print(confusion_matrix(yte, prediction))
```

`GridSearchCV` 在每折内拟合 Pipeline，并在选择参数后自动用全部训练集重新拟合。`best_score_` 是用于选择的交叉验证均分，不能与独立测试分数混为一谈。

<a id="sec-2"></a>

## 2. 结果应该怎样检查

先确认模型是否超过基线，再看各类召回率与混淆矩阵。若某类经常误判，检查该类样本量、分布重叠和特征异常，而不是立即增加模型复杂度。训练验证差距大时，可以比较更强正则；二者都差时，再考虑表示或容量。

<a id="sec-1-1"></a>

### 基础算例：分类报告的一行如何回到样本

某类支持数为 20、召回率为 0.75，表示其中 15 条预测正确、5 条漏到其他类。下一步查看这 5 条的预测类别、概率和特征范围，而不是只继续增加模型复杂度。宏平均 F1 给各类等权，不等于按样本数加权的总体表现。报告保留混淆矩阵和来源分组，使分数改善能对应具体错误变化，而非只有一个无法解释的均值。

<a id="sec-2-1"></a>

### 机制展开：指标变化应能回到错误样本

宏 F1 提高可能来自少数类改善，准确率提高可能由大类主导。对每类给支持数、混淆来源和置信分布，再追踪少量代表错误到原记录。没有错误标识就难区分标签问题、预处理问题和模型边界。探索发现应在开发数据形成对照；看过测试再改方案，需明确原测试已参与选择，不能继续当独立确认。

<a id="sec-3"></a>

## 3. 代码每一步对应一个实验职责

`train_test_split` 建立最终隔离边界，Pipeline 保证每折只使用训练统计量，GridSearchCV 在训练部分比较参数，`refit=True` 用选定参数重新利用完整训练数据。最终 `predict(Xte)` 才触及测试特征，测试标签只用于报告。

应保存 `cv_results_` 中的均分、波动与耗时，而不只保存最优参数。检查相邻正则强度的表现是否接近，可以判断最优点是否稳定。如果多个方案几乎相同，可优先选择简单、稳定的配置，而不是把噪声中的最大小数位当作可靠发现。

<a id="deep-dive-3"></a>

### 深入讲解：分类代码如何落实基线搜索与一次最终评价

先分出独立测试并保存索引，开发部分用于交叉验证和调参。Pipeline让缩放器仅在每折训练中拟合，模型在变换后的训练数据学习；外层测试只调用冻结后的整条预测流程。

多数类基线帮助看清类比例，逻辑回归或其他简单模型提供可解释参照。候选搜索的每次评价都消耗验证信息，不应因为代码循环方便就无上限尝试后宣称独立成功。

分类结果除了准确率，还要看混淆矩阵、每类支持、召回和概率质量。某类样本少时单次分数很不稳定，保留错误计数和样本，比四位小数更能解释效果。

若按测试错例设计新特征，测试已参与开发。可把该集重新标为开发信息并建立新独立评价，不能只换一个变量名继续称最终测试。

代码验收从固定输入预测到整套指标重算，核对类别顺序与概率列。运行成功证明接口闭环，是否学到可迁移关系还需当前分割和任务范围内的独立证据。

<a id="sec-4"></a>

## 4. 从分类报告定位错误

读取每类 precision、recall 与 support，再结合混淆矩阵看主要误判去向。某类 precision 低可能是其他类流入，recall 低则是自身大量流出。两者对应不同问题，不能只说“这类效果差”。

保存测试预测和真实标签用于审计，但根据这些错误继续修改模型后，原测试集已进入开发流程，下一轮需要新的独立评价。

<a id="sec-5"></a>

## 5. 综合算例与实现核对

运行后先确认基线与候选使用同一测试样本。接着查看搜索在每个正则系数下的交叉验证均值与波动，判断最优是否只是极小差异。最终 classification_report 的 support 与划分后的类别数应一致。

混淆矩阵按真实类行、预测类列解释，一行非对角是该类漏分去向，一列非对角是被误吸入的其他类。把某个主要混淆对对应原样本特征分布，才形成具体分析。

项目不应把最高测试分数作为继续选择模型的信号。若想加入随机森林，先在开发数据完成比较并固定方案，再用新的或原先真正保留的测试评估完整选择流程。

<a id="sec-6"></a>

## 6. 进阶：搜索结果与独立性能的不同对象

GridSearchCV 的 best_score 是在多个候选中选出的验证最大值，含选择乐观性；最终测试估计所选流程的未见表现。邻近参数分数接近时，可优先简单稳定配置，不应过度解释唯一“最优值”。

基线必须共享划分和指标。若加入新模型后根据测试成绩决定保留，就改变测试职责。复现表应包括全部预设候选、折内前处理、耗时与失败，而非只有最后最高一行。

<a id="sec-6-1"></a>

### 分类实验中每一个 fit 的信息来源

Pipeline 的 scaler 在每个交叉验证训练折估计均值与尺度，再把同样变换用于该折验证；GridSearchCV 比较候选后按规定规则在全部开发训练集 refit。最后测试预测不再拟合任何组件。逐个追踪 fit 发生在哪些行上，是识别泄漏的直接方法。

宏平均 F1 先按类别分别计算再平均，使每类等权；加权平均按支持数加权，含义不同。多数类基线可能拥有较高准确率却很低宏 F1，因此报告中应同时给各类支持数和召回率，不能只保留对候选最有利的一个聚合数。

若候选增加或搜索范围改变，要记录这本身也是流程变化。最终查看错误可形成下一轮假设，但据此调整后原测试不再独立。教学中可以继续探索，只需明确开发与最终评价角色，不把一张越来越好的测试表误认为连续独立验证。

<a id="sec-7"></a>

## 7. 练习与参考答案

**练习：** 将标准化移到划分数据之前，代码仍能运行，为什么结论却不可靠？

**答案：** 测试样本的统计量进入了训练前处理，破坏独立评估；能运行与流程正确是两回事。应保留 Pipeline 中的拟合边界。

<a id="sec-7-1"></a>

### 边界追问：宏平均改善能否忽略具体类别

**问题：** 宏 F1 提升但某个关键类别召回下降，能否直接称所有方面更好？

**推理解析：** 不能，平均掩盖取舍。给各类支持、混淆和代价，判断关键类别是否有约束。数据小的类别还需不确定性。错误分析用于形成可验证假设，不能事后按测试案例不断定制规则而继续称独立结果。
