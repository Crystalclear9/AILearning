## 1. 批量更新公式

从回放取状态、动作、奖励、下一状态与真正终止，在线网络输出当前 Q，通过动作索引选择预测；目标网络在 no_grad 中构造 TD 目标。损失可用平方或 Huber，更新后按协议同步目标网络。

```python
import copy
import torch
from torch import nn
torch.manual_seed(42)
online = nn.Sequential(nn.Linear(3, 16), nn.ReLU(), nn.Linear(16, 2))
target_net = copy.deepcopy(online)
optimizer = torch.optim.Adam(online.parameters(), lr=0.001)
s, ns = torch.randn(8, 3), torch.randn(8, 3)
a = torch.randint(0, 2, (8,))
r = torch.randn(8)
terminated = torch.tensor([False]*7 + [True])
prediction = online(s).gather(1, a[:, None]).squeeze(1)
with torch.no_grad():
    chosen = online(ns).argmax(1)
    future = target_net(ns).gather(1, chosen[:, None]).squeeze(1)
    target = r + 0.99 * (~terminated).float() * future
loss = nn.functional.smooth_l1_loss(prediction, target)
optimizer.zero_grad()
loss.backward()
optimizer.step()
assert torch.isclose(target[-1], r[-1])
```

本例随机转移只验证 Double DQN 一次更新的形状、梯度与终止边界，不声称学会环境任务。

<a id="deep-dive-1"></a>

### 深入讲解：DQN一次批量更新的张量与计算图责任

网络输出(B,A)动作值，gather按每条实际动作选成(B,)，对应当前Q(s,a)。奖励、bootstrap mask和下一值应同形，若一个为(B,1)另一个(B,)，广播可能产生(B,B)却仍能算loss。

下一状态目标在停止梯度上下文计算，真正终止令尾值零。Double先在线argmax得动作，再目标网络gather评值，不能分别在不同动作上取最大后仍称分离选择评价。

损失可用均方或Huber等约定，归约与权重需明确；优化器仅更新在线参数，目标同步在规定时刻独立进行。无意将目标参数也加入更新，会改变机制。

先用手工两条转移计算y与被选Q，核对未执行动作没有直接TD监督项，再检查梯度只到在线路径。随后测试全终止、无终止和不同动作索引。

这段局部更新不包含环境、回放和长期评价。它通过只证明批量公式被实现，训练稳定和策略收益还要在完整协议下独立确认。

<a id="sec-2"></a>

## 2. 区分扩展

Double DQN 分离动作选择与评价；dueling 结构分解状态价值与动作优势；优先回放按信号改变采样并需相应偏差考虑。不同扩展解决不同问题，不能只把名字叠加而忽略接口。

<a id="sec-1-1"></a>

### 基础算例：Double DQN 的两张网络承担不同角色

下一状态在线 Q 为 (5,4)，目标网络 Q 为 (2,6)。Double DQN 用在线网络选动作 0，再取目标值 2；普通目标网络 max 则取 6。两者不是把同一个 max 复制到两张网络。加上奖励、折扣与终止掩码后，目标停止梯度，只更新当前在线预测路径。人工设置这组值可清楚识别代码是否真正实现选择与评价分离。

<a id="sec-2-1"></a>

### 机制展开：不同 DQN 扩展修改不同环节

Double 分离选择与评价，dueling 分解状态与动作相关表示，优先回放改变采样分布；它们不是把同一网络复制几份的不同叫法。采样改变后还需说明权重修正与目标，组合扩展也不自动叠加收益。先在人工小批验证每项公式与梯度边界，再做固定预算消融，避免同时加入多个模块后无法解释改善。

<a id="sec-3"></a>

## 3. 一次更新中各张量的职责

当前状态输出八行两列，gather 只取每行实际动作的 Q。下一状态由在线网络选动作，再由目标网络评价，这就是 Double DQN 的分工；若直接取目标网络最大，则是标准 DQN 目标。两者不要仅凭变量名判断。

最后一条真正终止，所以目标严格等于奖励，断言专门检查这一边界。目标计算不追踪梯度，在线预测才参与反向。随机示例不能验证经验回放、探索和环境交互，完整任务还需这些组件与多回合评价。

可先保存更新前后参数确认发生变化，再检查目标网络是否按预设周期同步。若每步无意让目标与在线共享同一对象，所谓慢目标就不存在；复制结构与加载参数应明确区分引用。

回放存储还需避免可变数组被环境复用，必要时复制当前观察，否则历史经验会随后续步骤被改写。这类数据错误不一定引发形状异常，却会让学习目标混乱。

<a id="sec-4"></a>

## 4. 综合算例与实现核对

可将最后一条终止标志改为假，核对目标多出折扣未来值；再把目标网络输出人为设成常数，手算几个目标。这些小干预直接验证奖励、折扣和 mask，而不是只看 loss 有限。

优化后仅在线网络应发生梯度更新，目标网络在 no_grad 中保持不变，直到显式同步。若两者共享参数引用，目标会立即跟着变化，稳定机制失效。

正式训练还需回放抽样、探索调度、环境重置和评估。把单步更新独立检查后再组合完整循环，可以在回报失败时更准确地定位是估计、交互还是探索问题。

<a id="sec-5"></a>

## 5. 进阶：一次更新的梯度边界与算法差异

仅当前网络实际动作对应 Q 参与损失，下一状态目标在 no_grad 下固定。对所有动作回归同一 target 会错误监督未执行动作；在线与目标若共享同一对象，慢目标机制也不存在。

Double 选择评价、dueling 结构分解、优先回放改变采样，分别解决不同问题。将它们组合时要核对目标与偏差修正，而非只叠名称。随机转移单步测试只能验证接口，不能证明探索和环境学习成功。

<a id="sec-5-1"></a>

### 一次 DQN 更新应画出梯度边界

给定回放批次，当前预测用在线网络读取所选动作 $Q_\theta(s,a)$，目标为 $r+\gamma b\max_{a'}Q_{\theta^-}(s',a')$。目标通常停止梯度，损失只更新当前在线参数；目标网络由指定的复制或软更新规则改变。

动作张量用于 gather 时要与批索引对应，奖励、掩码和预测统一为批向量或同形列向量，避免广播成批×批矩阵。一个人工批次可同时放普通转移和真正终止转移，分别手算目标，再检查哪些参数获得梯度。

Double DQN 改的是目标动作选择与评价的分工，不等于只把网络复制两份。Huber 损失改变大 TD 误差的梯度，不自动保证正确样本或稳定学习。更新函数测试通过后，还要验证采样、环境步与评价闭环，因为局部正确不能替代整个算法运行。

<a id="sec-6"></a>

## 6. 练习与解析

**题目：** 当前动作 a 为 1，为什么不能直接将输出两个 Q 值都与同一 target 比较？

**解析：** 这条转移只观察了动作 1 的结果，对另一个动作没有同样监督。应只更新相应动作，参数共享的间接影响另当别论。

<a id="sec-6-1"></a>

### 边界追问：Huber 损失能否修复目标动作选错

**问题：** 代码 gather 了错误动作，改用更稳的 Huber 后 loss 不爆炸，是否已修复？

**推理解析：** 没有，损失形状改变梯度尺度，不恢复正确语义。人工设置不同动作值核对索引、Double 选择评价与终止，再检查梯度边界。数值稳定与目标正确各需证据，平稳曲线也可能在稳定优化错误函数。
