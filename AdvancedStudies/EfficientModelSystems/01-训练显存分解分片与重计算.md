## 1. 峰值显存由哪些状态组成

对 P 个参数，训练状态可能包括低精度模型权重、梯度、FP32 主权重及优化器矩。另有前向激活、通信缓冲、临时工作区、分配器缓存和碎片。总和不是简单“参数量乘权重位宽”，峰值还取决于这些对象何时同时存活。

一个示例预算：低精度权重 2P 字节、低精度梯度 2P、主权重 4P、Adam 两矩 8P，合计 16P。实际框架可采用 FP32 梯度、不同主权重方案或其他优化器，必须先确认配置，不能将 16 当作所有训练的普遍常数。

推理通常不需要优化器与训练梯度，但可能出现较大 KV cache 和并发工作区，问题已不同。把训练显存策略直接拿来估计服务内存会遗漏主要对象。

<a id="sec-2"></a>

## 2. 数据并行为什么复制状态

普通同步数据并行让每个设备持有完整模型与优化器，各自处理不同数据，再归约梯度。全局批大小通常为每设备微批×设备数×累积步数；梯度是求和还是平均、损失按样本还是 token 归约，决定与单设备参考是否等价。

增加设备本身不减小每卡模型状态；若只是缩小每卡激活，可以通过改变微批达到。模型本身超出单卡时需要分片、张量或流水线并行等方案，而非仅再套数据并行。

<a id="deep-dive-2"></a>

### 深入讲解：有效token归约怎样决定多设备是否真的等价

设第i卡有Ni个有效token，局部均值loss为Li，目标应是ΣNiLi/ΣNi。若框架平均D卡梯度，局部反向需相应乘DNi/ΣNi，才能得到全局token均值，而非等权卡均值。

两卡分别2与6个token、局部梯度g1与g2，目标梯度为(g1+3g2)/4。直接平均会给第一卡过大权重。梯度累积跨多个微批时，也应对整个有效更新的分母处理，不能每个不等长微批等权除次数。

这一差别会影响与单卡参考的一次更新，不只是日志。先用小确定模型核对损失、梯度和参数，再加入随机层、分片、混合精度和重计算，逐项观察等价边界。

状态分片减少持久复制，激活检查点减少保存，累积减少微批激活；它们针对不同对象。实际峰值还有参数聚合与缓冲，不能把理想均分值当硬上限。

性能比较保持信息、目标与有效批可比，再报告通信、显存、吞吐和延迟。若优化同时改变归约，结果差异中就包含学习目标变化，不能全部称系统提速。

<a id="sec-3"></a>

## 3. 状态分片的机制与边界

ZeRO 的典型分阶段思想是逐步分片优化器状态、梯度和参数。全分片时，每设备长期保留部分状态，在需要计算某层时聚合参数，计算后释放或重新分片；梯度通过适当归约回到拥有者。

理想持久状态可随设备数 D 减少到相应比例，但计算时需要全参数片段、通信缓冲及在途激活，实际峰值不会简单等于总状态除以 D。粒度太小增加通信调度，粒度太大增加聚合峰值；预取可重叠通信，却提高同时存活量。

检查点也需说明保存全状态还是分片状态，恢复是否要求同样并行拓扑。一个“保存成功”日志不保证换设备数后可恢复完整优化器。

<a id="sec-3-1"></a>

### 进一步推导：通信量与计算重叠的预算

以 D 个设备、每设备需归约 N 字节梯度的理想 ring all-reduce 为例，每设备通信量主项约为 $2(D-1)N/D$，包含 reduce-scatter 与 all-gather 两部分。它帮助估算带宽需求，但实际延迟还取决于消息大小、拓扑、并发及框架调度，不能只除以标称链路带宽作为端到端时间。

全分片训练又包含参数聚合和梯度回分，次数取决于分片层级、前后向重聚合与预取。与普通数据并行相比，节省持久状态可能增加关键路径通信；慢网络或很小计算块会限制收益。张量并行需要在层内通信，流水线并行又引入阶段气泡，两者并非状态分片的简单别名。

激活预算也应按张量形状记录。常规 Transformer 中许多中间量随 B×T×d 增长，朴素注意力分数还有 B×h×T²；具体保存数量、精度和重计算内核决定常数。仅按参数状态分片仍可能在长序列时因激活耗尽显存。

性能排查先看时间线上是否有计算等待参数、归约尾部或流水线空闲，再决定扩大块、调整预取或改变并行策略。通信与计算理论上能重叠，不代表当前实现已重叠；为了测量而每层强制同步还会改变原调度。

<a id="sec-4"></a>

## 4. 基础算例：先估算再测量

取 P=10亿、D=8，采用第 1 节假设。复制状态每卡约 16 GB；仅优化器两矩分片，粗估为 $(2+2+4)P+8P/D=9$ GB；全部模型训练状态理想分片约 2 GB。这里 GB 是十进制，不是 GiB，而且均未计激活和聚合峰值。

若实际观测仍为 12 GB，不能立即断言分片错误。应查看各层临时参数、激活、通信工作区和统计口径，区分已分配与已保留内存。逐项测量比拿理想数值当硬上界更有效。

<a id="sec-5"></a>

## 5. 重计算、累积与卸载各换什么

激活检查点减少保存中间结果，在反向时重做部分前向，换取更低激活内存；分片减少复制的持久状态；卸载把状态搬到 CPU 或其他存储，换取传输和延迟成本。三者针对不同对象，可以组合但相互影响。

梯度累积减少一次前向所需微批，不减少模型状态；含 BatchNorm 等批耦合操作时，也不与真正大批完全等价。重计算需保持所需随机行为与状态一致，含副作用的前向不能随意再执行。某些注意力融合内核减少中间存储，又是另一种 I/O 优化。

<a id="sec-6"></a>

## 6. 验证正确性与扩展效率

先用小模型和固定输入比较单设备参考及并行实现的损失、有效梯度、一次更新与保存恢复。保持同样初始化、归约与随机层协议，允许有说明的浮点误差；若不一致，先定位语义差异，再测性能。

性能实验同时记录峰值显存、端到端每步时间、通信等待、全局批量及实际 token。强扩展固定总工作量，弱扩展改变总工作量，结论不同。加入预取、累积或卸载后再测瓶颈，避免只是从显存限制移到通信限制。

<a id="sec-7"></a>

## 7. 练习与解析

**练习一：** 八卡数据并行为何可能仍每卡放不下模型？

**解析：** 普通复制数据并行不分片模型状态，卡数增加不直接降低这部分每卡内存。

**练习二：** 分片理论节约八倍，峰值只有三倍改善，是否必有错误？

**解析：** 不一定，激活、聚合与工作区可能未按同样比例减少，需分解测量。

**研究练习：** 为给定模型分别列出权重、梯度、优化器、激活和通信预算，选择分片及检查点策略。先给理论估计，再用代表负载测量差异，解释内存收益与每步变慢分别来自哪里。
