## 1. 从实数到量化格点

一种仿射量化写为 $q=clip(round(x/s)+z,q_{min},q_{max})$，反量化为 $\hat x=s(q-z)$。s>0 是尺度，z 是零点；对称量化常取合适的零点，不对称形式用于更一般范围。整数范围、饱和和舍入规则必须说明。

误差包含格点舍入与超范围裁剪。非饱和时最近舍入误差通常不超过 s/2，裁剪后不再有这个全局界。逐张量尺度省元数据，但不同通道范围差大时可能损失精度；逐通道或分组尺度更灵活，增加元数据和访存。

<a id="sec-2"></a>

## 2. 权重误差不等于输出误差

对线性层 Y=WX，量化误差 E=Ŵ−W，输出误差为 EX，平方 Frobenius 误差是 $tr(E XX^T E^T)$。因此校准激活的方向和相关性影响实际损失，同样权重均方误差可能对应完全不同输出误差。

基于校准样本的重构方法利用这种几何选择或补偿量化误差。校准集应代表部署长度、输入与激活范围，且不能用最终测试标签反复调参。GPTQ 等方法涉及近似二阶信息及逐步补偿，不能简化成所有权重独立四舍五入。

<a id="sec-2-1"></a>

### 进一步推导：校准几何、元数据与整数实现边界

将 X 的各列看作校准激活，$XX^T$ 给出输入方向的未归一二阶结构。若某方向激活能量大，同样权重误差投向它会造成更大输出偏差；相关通道还会让误差相互抵消或叠加。逐权重最小绝对误差与最小层输出误差的最优方案因此可能不同。

分组量化的存储也可显式估算：P 个 b 位权重、每 G 个共享一份 $b_s$ 字节尺度元数据，理想大小约为 $Pb/8+Pb_s/G$（这里 $b_s$ 是存储字节数，不是第 1 节的量化尺度 s）；若还需零点、对齐和例外通道继续相加。很小组提高灵活度，却增加元数据和解包成本，不能只按名义位宽排序。

整数实现中要在足够宽的类型计算 q−z、乘法与累加，避免窄整数溢出；真实内核可能使用整型乘加或转为较高精度，不应从文件格式推断全部算子。饱和范围、舍入及累加方式应与校准时的模拟一致，否则离线误差评估不代表实际部署行为。

校准集过小或只含短输入时，长上下文和罕见激活可能落到未见范围，裁剪误差不再是一般舍入界。应把校准选择固定在开发阶段，并在独立目标负载检查；若需要为新场景重新校准，说明其新增信息与版本。

<a id="deep-dive-2"></a>

### 深入讲解：相同权重误差为何在两个输入分布上后果相反

取一行权重误差E=(a,−a)。若输入总为(1,1)，输出误差Ex=0；若输入为(1,−1)，则Ex=2a。误差范数完全相同，实际层误差却不同，说明校准输入的方向和相关性至关重要。

平方输出误差由tr(EXXᵀEᵀ)决定，XXᵀ给输入二阶几何。校准集只覆盖某子空间时，在该集误差极小不保证新方向同样好；代表性与独立目标负载都需要检查。

逐张量、逐通道和分组尺度改变可适应范围，同时增加元数据。名义4bit之外还存尺度、零点及例外层，实际容量和内核访问未必按4/16精确缩小。

舍入误差界只在非饱和条件下成立。范围外值被clip、窄整型相减累加溢出、模拟与真实内核规则不一致，都会改变结果；应核对具体数值路径。

验收从层输出到完整任务，再到目标硬件内存与延迟。压缩文件更小、困惑度近似和用户任务更快是三种不同收益，不能用其中一种替代全部。

<a id="sec-3"></a>

## 3. 权重、激活与缓存分别决定成本

权重量化主要减小模型存储和权重读取，激活量化改变计算与中间量，KV 量化针对长序列和并发缓存。只量化权重不代表整个推理都用同样低位整数，常见实现含解包、反量化及混合精度累加。

假设模型有 P 个权重、每权重 b 位，理想原始存储为 Pb/8 字节；还要加尺度、零点、未量化层和布局开销。是否更快取决于硬件支持、内核、批量及瓶颈，压缩四倍不能直接说延迟变四分之一。

<a id="sec-4"></a>

## 4. 基础算例：一个输出误差核对

采用有符号范围 [-7,7]、尺度 0.1，权重 (0.12,−0.27,0.68) 反量化为 (0.1,−0.3,0.7)。误差点积随输入改变；第三维权重误差虽小，若该维激活很大仍可主导输出。

```python
import numpy as np
w = np.array([0.12, -0.27, 0.68])
scale = 0.1
q = np.clip(np.rint(w / scale), -7, 7).astype(np.int8)
restored = scale * q.astype(np.float64)
error = restored - w
x = np.array([1., 1., 100.])
assert np.allclose(restored, [0.1, -0.3, 0.7])
assert np.all(np.abs(error) <= scale / 2 + 1e-12)
assert np.isclose(restored @ x - w @ x, error @ x)
print("weight error:", error, "output error:", error @ x)
```

若输入权重超过允许范围，舍入误差界不再适用。该例只核对量化语义，不实现 GPTQ，也不证明端到端任务无损。

## 5. 用算术强度理解速度

粗略 roofline 思路将运算吞吐上限看作峰值算力与带宽×算术强度两者较小值；算术强度是每搬运字节对应的运算量。单请求 decode 可能大量读取权重而每步只处理少量 token，prefill 大矩阵则更能复用权重，瓶颈可不同。

批处理增加复用，可能提高总吞吐，却改变排队与单请求延迟；长上下文又增加 KV 读取。测量时分别看首 token 延迟、逐 token 速度、并发吞吐和尾部等待，不用一个 tokens/s 解释所有服务条件。

<a id="sec-6"></a>

## 6. 量化方案的验收

先固定原精度基线、数据、解码与硬件，检查若干层输出误差和端到端任务结果；按长度、稀有 token、困难样本及数据来源分组。困惑度接近不保证格式、工具选择或长文本任务也保持，实际评价应覆盖目标功能。

同时记录实际权重与缓存容量、峰值内存和代表并发下延迟，包含预热、反量化和缓存行为。若某方案只减少文件大小而速度未变，就如实报告压缩收益；需要更快内核或更大批量时，说明其适用条件而非强行宣称全场景加速。

<a id="sec-7"></a>

## 7. 练习与解析

**练习一：** 权重误差最小的方案是否一定输出误差最小？

**解析：** 不一定，误差方向与输入协方差相互作用，输出目标权重不同。

**练习二：** 量化后 GPU 利用率升高，是否证明用户延迟更低？

**解析：** 不证明，排队、解包和其他阶段可能抵消，需要端到端测量。

**综合练习：** 用两种激活分布校准同一线性网络，比较逐张量及分组尺度。分别报告存储、层输出误差、独立任务质量和延迟，解释校准分布改变为何影响结果。
