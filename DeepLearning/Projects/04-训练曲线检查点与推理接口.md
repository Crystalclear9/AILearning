## 1. 保存可解释的历史

每个 epoch 记录训练损失、验证损失、验证准确率、学习率和耗时。画曲线时标明平均规则与训练预算。训练下降验证上升提示过拟合，但还要核对模式、增强和损失定义。

epoch 训练损失按样本数或有效 token 数加权汇总，验证采用相同目标定义；若训练含增强或额外正则，应把数据项与正则项分开记录，避免直接比较不同意义的曲线。学习率变化和恢复训练位置也应标在历史中。

检查点选择只依据预定验证规则，日志同时记录对应步数及配置。恢复时追加历史而不是覆盖旧记录，重复运行使用不同运行标识。展示平滑曲线时保留原始点与平滑窗口，不能将抖动完全抹去后再据此宣称训练稳定。

<a id="sec-2"></a>

## 2. 检查点与恢复

保存模型、优化器、轮次、最佳验证值与配置。恢复时先重建相同结构，再加载状态；检查依赖与设备。仅保存最优权重适合推理，却不足以无缝恢复训练轨迹。

<a id="sec-2-1"></a>

### 机制展开：最近检查点与最佳检查点可并存

最近状态便于故障恢复，最佳状态对应既定验证选择；两者不能仅用一个含糊文件覆盖。保存元数据应映射轮次、更新步、优化器、调度、配置与选择指标。日志的时刻也需和状态对应。恢复演练从新进程读取，先核对固定预测，再检查后续更新所需状态，最后核对最终报告是否使用预期的最佳版本。

<a id="deep-dive-2"></a>

### 深入讲解：检查点与推理接口怎样保持同一个预测函数

推理契约包括输入通道、数值范围、尺寸、批维、类别顺序及输出解释。模型权重相同但归一或映射变了，函数已经不同；文件能加载不证明部署一致。

检查点有最后状态和最佳验证状态，使用目的不同。恢复训练还需优化器、调度器和必要随机状态，保存步数与配置；只恢复权重是新训练起点，不必与连续训练同轨迹。

日志在每epoch或step记录损失、验证、学习率、耗时，明确归约与更新前后。中断后追加历史应保留运行身份，不能把不同配置曲线无说明拼接。

用已知样本分别经过训练评价入口和部署入口，比较中间张量及输出。这个测试能定位前处理、模式、dtype与类别映射，而不只是最终概率近似。

产物写入成功后实际重载，检查输出完整。把保存、恢复、评价职责分开，可避免日志函数改变训练或检查点对应不上报告数字。

<a id="sec-3"></a>

## 3. 推理契约

输入要求单通道 8×8、像素按量程归一化，输出为 10 类 logits 或固定映射后的类别。接口应检查维度与类型，并明确是否返回概率。批量推理与单图推理应在同一模式下给出一致对应结果。

<a id="sec-1-1"></a>

### 基础算例：固定输入先检查推理契约

同一张图分别以单样本和包含它的批量输入，在正确评估模式下，应得到容差内一致的对应输出；若网络存在明确跨样本机制则另作定义。检查通道、归一化、类别顺序和权重版本，确认推理入口不依赖重新训练。随后再演练中断恢复，核对优化器与调度状态。固定预测一致证明当前函数恢复，不等于未来训练轨迹也完全一致。

<a id="sec-4"></a>

## 4. 日志与保存策略要一致

每轮计算验证损失后，与历史最优比较并保存同一状态，日志同时记录最佳轮次。若保存发生在下一轮更新之后，记录与权重会错位。恢复训练时区分“最近状态用于继续”和“最佳状态用于推理”，两者用途不同。

推理接口应接收明确范围和形状，不把是否归一化留给调用者猜测。可以对输入做范围检查，并用一批已知样例测试保存加载前后输出一致。若批量维缺失，按协议补维而非随意 reshape 改动像素顺序。

训练曲线展示时保留选择依据。最佳准确率和最佳损失可能不在同一轮，报告要注明用哪一个选择，避免事后从多个指标挑最有利权重。最终测试只评估确定状态。

<a id="sec-5"></a>

## 5. 综合算例与实现核对

设计一次恢复演练：训练若干轮，保存最近检查点，重新启动并恢复，再继续一轮。核对轮次、学习率、优化器状态与数据配置，确认不是从初始动量重新开始。若要求严格续接，还要考虑随机数与采样状态。

另做推理演练：用同一模型分别预测单张与对应批量，核对类别映射与输出是否一致。若含 BatchNorm，必须在评估模式进行；否则同图可能受同批其他图影响。

最后检查输出目录中的模型、配置和日志是否相互对应。文件名只写 best 不足以区分多个实验，应关联实验标识和选择指标。这个小型演练让保存步骤成为可用功能，而非只在代码里出现一行 save。

<a id="sec-6"></a>

## 6. 进阶：续训等价与推理等价

保存加载后 logits 一致只证明当前函数恢复；继续训练一致还需优化器、调度、随机数、数据顺序和模式等状态。若存在非确定算子，还应按容差或统计一致而非强求逐位一致。

交付需固定图像形状、范围、通道与类别映射。单图和批预测应在评估模式核对。最近状态用于恢复，最佳状态用于最终推理，两个产物要分清，不能拿错误文件解释报告指标。

<a id="sec-6-1"></a>

### 日志、最近状态与最佳状态应一一对应

训练日志中的 epoch、更新步和学习率应能映射到实际检查点。若保存发生在更新前而日志记录更新后，恢复后会出现看似无法解释的差异。设计保存点时明确参数、优化器和调度器处于哪一时刻。

最近检查点服务于断点恢复，最佳验证模型服务于最终推理；最佳模型可能来自较早轮次。推理交付不需要启动训练，应能从固定结构、权重和预处理直接产生输出，并对未知类别或非法形状给出明确行为。

恢复演练应在新进程进行，先比较固定输入 logits，再检查继续训练所需状态。若要求严格轨迹一致，还需控制随机数、数据顺序和算子确定性；若目标仅为统计稳定，需说明允许的差异与验收标准，避免把不同层次的复现混为一个通过标记。

<a id="sec-7"></a>

## 7. 验收练习

选一批测试输入，保存模型再加载，对比前后 logits 的容差一致；核对类别顺序与归一化；确认代码无需训练即可读取检查点预测。

**解析：** 这个验收检查模型函数交付，不代表新的泛化证据。指标复现还要固定数据划分与评价代码，两部分应分别验证。

<a id="sec-7-1"></a>

### 边界追问：单图与批量推理不一致一定是保存坏了吗

**问题：** 同图在不同批量输出有差异，首先该检查什么？

**推理解析：** 先核对 eval、BatchNorm、随机层、预处理和模型是否含显式跨样本操作，再查数值容差与状态。序列化只是一个可能因素。固定完整输入契约并比较中间值，可以区分模式、数据与产物问题，不应无依据反复重新训练。
