## 1. 选择可控的数据任务

使用 scikit-learn 内置手写数字数据集，每张图为 $8\times8$ 灰度图，类别为 0 到 9。小数据便于在 CPU 上理解全流程。与更大数据相比，它不能代表复杂真实图像的泛化难度，但适合检查数据、网络和训练代码是否衔接正确。

像素原值约在 0 到 16 之间，可除以固定量程 16。这种基于已知量程的变换与从全数据估计均值不同，不需要学习测试统计量。图像形状变为 $(N,1,8,8)$，标签为整数类别。

<a id="sec-1-1"></a>

### 基础算例：像素量程变换与统计量拟合的区别

内置数字像素已知量程为 0—16，统一除以 16 是使用预先规定的单位变换；改为减全数据均值则从测试输入估计了统计量。两者信息来源不同。划分后逐批检查图像、整数标签、类别数量和量程，再进行小样本拟合。先让十几条样本的 loss 明显下降，可以检验训练机制；此时仍不能推断独立测试效果，两个验收目的需分别说明。

<a id="sec-2"></a>

## 2. 三份数据各司其职

先固定分层测试集，再从剩余数据划出验证集。训练集优化参数，验证集选择 epoch 与设置，最终测试只评估确定的模型。基线可使用展平输入的逻辑回归，帮助判断 CNN 是否真的带来收益。

预先确定主要指标为准确率，并按类别查看召回率。记录每个 epoch 的训练平均损失、验证平均损失和验证准确率；最终报告还应保存模型配置、种子和依赖版本。

<a id="sec-2-1"></a>

### 机制展开：选择指标可以不同于最终报告指标

用验证交叉熵选权重、用测试准确率报告是可定义协议，但需事前固定，因为最低 loss 与最高 accuracy 未必同一轮。不能训练后在多个指标之间挑最有利状态。划分与选择决定证据范围，量程转换和可学习统计也要分清。预先保存索引、类别支持与主要规则，比事后只记录一个种子更完整。

<a id="sec-3"></a>

## 3. 训练前检查

随机查看若干图像和标签，确认类别没有错位。检查一个批次的范围、形状和数据类型。尝试仅拟合十几条样本，确认训练损失能显著下降；之后恢复完整划分和正常正则设置。

除查看图像，还应统计每类数量、重复和来源，确认索引划分没有重叠。读取一个批次时记录 NCHW 轴顺序、归一化前后范围和标签 dtype；对类别编号选一两个样例反查类别名，避免可运行却整体错位。

极小集拟合是训练链路检查，不是泛化证据。完成后恢复正常数据划分、增强、正则和评估模式，并重新初始化模型，避免把排错阶段已看过的测试样本混进正式训练。若极小集仍不能下降，先排查损失和梯度，不急于扩充模型。

<a id="deep-dive-3"></a>

### 深入讲解：把训练前检查做成从原图到loss的可解释路径

先查看原图、标签和来源，确认类别映射与独立划分。加载一批后核对NCHW轴、dtype、范围与归一；增强后的图也应可视化，避免输入已被无意破坏。

用十几条样本、简化随机与正则，检查是否能明显拟合。若不能，优先查标签、输出、loss、梯度和参数更新，不直接加深网络；若能，只说明训练链路基本可用，不是泛化证据。

训练验证测试各有角色，按预设验证指标选状态。测试集若被用于观察错误后设计增强，已参与开发，后续评价需调整证据范围。

实验只改变一个主要因素，记录预算、初始化与有效样本。数据版本或索引变化也应被记录，否则两次分数可能根本不对应同一任务。

最终要求能解释一个批次如何得到目标和梯度、一次更新改变什么，以及独立测试测的是什么。这比仅运行完整脚本更能说明项目理解已闭环。

<a id="sec-4"></a>

## 4. 基线可以揭示网络是否必要

手写数字数据简单且分辨率低，线性或传统模型可能已经很强。CNN 没有明显超过基线，不一定表示代码出错，也可能是任务规模与训练预算下其结构优势有限。应同时比较参数量、训练成本和错误类型。

输入检查应包含类别分布、最小最大像素值、空白图与重复图。项目中的随机分层划分是教学协议；若真实任务面对新书写者，应按书写者划分。数据集能否支持某种泛化结论，要由其采样与标识信息决定。

<a id="sec-5"></a>

## 5. 数据版本与实验目标

先固定内置数据版本、划分规则和主要指标，确定基线与候选。项目中改网络、优化器和增强时逐项记录，不把许多变化混在一次实验后归功于一个模块。

验证目标也要清晰：本项目用于学习小图像分类闭环，不支持大规模视觉或新设备泛化结论。结论范围要与数据来源相匹配。

为每次实验记录稳定的数据标识、样本索引和配置，使同一名称的训练集不因随机调用顺序或源文件变化悄悄变动。验证集在开发开始时固定，类别覆盖及近重复检查一起完成。

实验假设写成可证伪问题，例如“轻量增强是否改善新笔迹错误”，并预定主要指标和预算。若同时增加数据、网络和训练时间，结果只支持完整方案改善，不能证明单一模块有效。项目范围是当前小图像闭环，外推到新设备需另建独立评价。

<a id="sec-6"></a>

## 6. 进阶：预注册比较与资源混杂

设定主要指标、验证选择和预算后，再比较 MLP、CNN 或优化设置。若新模型同时使用更多训练、分辨率和增强，不能把收益归给架构。项目应通过单因素或合理因子设计分离原因。

内置小图像数据只能支持该协议的教学结论；新书写者、设备与场景需要相应来源划分。模型是否必要应先和强简单基线比较，并报告成本，不以任务小为由省略独立评价。

<a id="sec-6-1"></a>

### 数据协议应先于网络与增强固定

手写数字小项目使用固定量程除以 16，可避免从测试样本估计尺度；若改用均值标准化，则统计量只来自训练部分。划分后核对各类别支持数和重复样本，标签与图像的共同索引不能在独立打乱中失配。

分类准确率是报告指标，最佳检查点可按验证损失选择，两者可以不同，但规则必须事先写清。若每次看到验证结果就调整许多设置，验证也存在选择效应；最终测试只用于确定方案的评价，不用于决定新的增强。

项目范围应明确为同数据来源下的教学闭环。按新书写者泛化需要相应实体标识和划分，不能把随机图像划分自动解释成该证据。先建立线性或 MLP 基线，再比较 CNN 的成本与错误类型，可以判断结构收益是否值得额外复杂性。

<a id="sec-7"></a>

## 7. 练习与参考答案

**练习：** 如果原像素范围固定为 0 到 16，除以 16 是否属于测试信息泄漏？若改成除以全数据标准差呢？

**答案：** 已知量程不是从测试数据估计的统计量，通常不构成泄漏。全数据标准差则使用了测试分布，应只从训练集估计。

<a id="sec-7-1"></a>

### 边界追问：小数据高分能否推新来源泛化

**问题：** 随机划分内置数字结果很高，是否已经验证新书写者或新设备？

**推理解析：** 没有，相应结论需要来源标识和部署匹配划分。教学闭环检验数据、训练与评价是否衔接，不自动支持所有真实场景。保存类别支持、重复检查与任务范围，再用简单基线判断 CNN 是否在当前预算带来额外价值。
