## 1. 从浅层特征到任务输出

早期层常捕捉局部边缘和纹理，后续层组合更大范围模式；这种经验不意味着每层都有固定语义。典型分类 CNN 由卷积、激活、下采样及分类头组成。全局平均池化把每个通道汇成一个值，可减少全连接层参数并适应一定的空间尺寸变化。

残差块形如 $h=x+F(x)$，提供直接的信息与梯度路径；若通道或分辨率不同，需用投影等方式对齐，不能把不同形状直接相加。

<a id="sec-2"></a>

## 2. 一个可运行的尺寸实验

```python
import torch
from torch import nn
model = nn.Sequential(
    nn.Conv2d(3, 16, kernel_size=3, padding=1),
    nn.ReLU(),
    nn.MaxPool2d(2),
    nn.Conv2d(16, 32, kernel_size=3, padding=1),
    nn.ReLU(),
    nn.AdaptiveAvgPool2d((1, 1)),
    nn.Flatten(),
    nn.Linear(32, 10),
)
x = torch.randn(4, 3, 32, 32)
print(model(x).shape)  # torch.Size([4, 10])
```

这个实验只验证前向接口，并没有训练出有意义的分类器。完整训练还需标签、损失、优化器和独立验证。

<a id="sec-2-1"></a>

### 机制展开：展平维度要从真实前向推导

卷积与池化每步改变通道和空间，最后线性层输入应等于 C×H×W。若输入分辨率变化，这个数也可能变化；自适应池化可固定输出空间，但同时改变信息汇总方式。尺寸实验只验证接口，不能证明分类任务有效。先用小批前向列出形状，再训练并评价，避免在错误展平处用随意 reshape 凑齐元素数。

<a id="sec-3"></a>

## 3. 数据少时如何迁移

可先冻结预训练骨干，只训练分类头，再用较小学习率微调部分或全部层。输入归一化、尺寸与通道顺序应符合预训练权重要求。数据增强只对训练集随机应用；验证预处理应稳定且符合部署。

若原任务与新数据差异很大，预训练未必带来同等收益。还需检查训练验证是否出现同一对象、同一视频相邻帧等近重复泄漏。

<a id="sec-1-1"></a>

### 基础算例：冻结骨干后仍要核对运行状态

将卷积参数设为不求梯度后，只训练分类头，并不必然冻结 BatchNorm 的运行均值方差；它们属于状态，是否更新还取决于模式。可在训练一步前后比较权重与缓冲区，分别确认预期行为。迁移学习同时需要匹配像素量程、通道顺序和归一化。只加载相同权重却更换输入协议，得到的并非原预训练函数在同样输入分布下的结果。

<a id="deep-dive-3"></a>

### 深入讲解：迁移学习怎样在固定表示与全量适应之间选择

冻结骨干只训练头，等于把预训练表示当固定特征，训练成本较低但适应能力受限。逐层解冻或全量微调允许改变表示，也需要合适学习率和足够独立验证，不能因参数更多就默认更好。

先匹配预训练输入约定：颜色、尺度、尺寸及类别头。输入分布不同可能让原表示失效；随机初始化基线与同预算比较能判断预训练实际带来多少信息优势。

冻结权重不自动冻结运行统计，BatchNorm模式要单独设定。若小数据批统计不稳定，可比较合理策略，但选择必须在验证完成。训练增强与评价固定流程也应分开。

分类头通过池化将空间特征转任务输出，细粒度定位任务可能需要保留更高分辨率。一个在分类上优秀的骨干，不代表无需改动就适合小目标和分割。

实验记录解冻层、学习率组、轮数、预训练来源和总成本。结果说明是完整迁移方案收益，若同时改变数据增强和训练预算，不能把全部提升归为某个结构。

<a id="sec-4"></a>

## 4. 冻结参数不等于冻结所有行为

把骨干参数的 `requires_grad` 设为 False，会停止这些参数的梯度更新，但 BatchNorm 的运行统计量在训练模式中仍可能改变。小样本微调时，需要根据目的选择哪些子模块保持训练模式、哪些使用已有统计量。

还应给分类头与骨干设置合适学习率，防止少量新数据迅速破坏已有表示。比较冻结与全量微调时，保持数据、增强和预算一致，观察是否只是训练更充分造成差异。模型在原始图像分布上的预训练优势，也可能因新图像风格、尺度或通道不同而减弱。

<a id="sec-5"></a>

## 5. 数据增强与验证分布

裁剪、翻转和颜色扰动都隐含标签不变假设。训练中随机改变图像，验证应使用明确固定协议；若采用多裁剪或测试时增强，须报告额外推理成本。

微调选择应在验证完成，不能看测试分数后决定冻结多少层。预训练优势也取决于源数据与目标任务差异，应与适当基线比较。

迁移学习时还要对齐预训练输入约定，包括颜色、归一化与尺寸。冻结权重不一定冻结 BatchNorm 运行统计，训练和评价模式需明确；微调更深层应有验证收益而不是仅凭预训练经验。

增强消融保持其他因素固定，检查方向敏感、小目标或颜色敏感子集。测试时增强相当于额外推理与预测汇总，需要与单次前向分开报告。源预训练数据、目标标注量和总计算不同的比较，只能说明完整方案差异，不能单独解释为架构优势。

<a id="sec-6"></a>

## 6. 进阶：卷积结构的归纳偏置与迁移

局部连接和参数共享降低自由度，适合存在重复局部模式的数据；如果位置本身具有强语义，过强共享也可能不合适。坐标特征、位置编码或其他结构是在调整假设，而非仅增加装饰。

冻结参数不冻结 BatchNorm 运行统计，微调头与全网络时模式和学习率需分别设计。迁移收益可能来自数据、优化与正则共同作用，应与从头训练和冻结基线在一致协议下比较，不能把单次高分归为普遍架构优势。

<a id="sec-6-1"></a>

### 迁移学习先区分参数、状态与输入协议

冻结 backbone 参数仅阻止这些参数更新，不一定阻止运行统计变化。含 BatchNorm 的网络若仍处训练模式，均值方差状态可能继续更新；dropout 也由模式控制。迁移实验需同时记录哪些参数可训练、哪些状态可变和每部分采用的模式。

预训练权重通常依赖输入通道、像素范围和归一化规则。把不同颜色顺序或不同量程直接输入，模型仍可能返回 logits，却已偏离预训练输入分布。先用官方对应预处理建立基线，再研究改变协议的收益。

线性探测只训练新头，成本低且便于判断已有表示；全量微调更灵活，却可能在小数据上过拟合或破坏已有特征。可比较相同数据划分下的验证效果、收敛成本与域外表现，不能只以训练分数判定微调范围。

<a id="sec-7"></a>

## 7. 练习与参考答案

**练习：** 人脸照片随机分到训练和测试，但同一人的不同照片出现在两边，是否能代表识别新人的能力？

**答案：** 不能。模型可能利用身份特征，评估的问题与新身份泛化不同。若目标是新人的属性预测，应按身份分组划分。

<a id="sec-7-1"></a>

### 边界追问：迁移效果差是否必须全量微调

**问题：** 冻结骨干的结果不佳，是否立刻说明需要更多可训练层？

**推理解析：** 先核对输入量程、颜色顺序、归一化、标签与模式，错误协议也会破坏预训练表示。再用固定数据比较头部、部分解冻与全量方案及成本。小数据上更多可训练参数可能过拟合，训练分数不能替代独立验证。
