## 1. 从线性投影到头维

输入 $(B,T,D)$，投影 Q、K、V 后变为 $(B,T,H,d)$，再转置成 $(B,H,T,d)$。点积在最后两轴进行，每个头分别形成 $(T,T)$ 关系，最后合并头并输出投影。

```python
import torch
from torch import nn
torch.manual_seed(42)
B, T, D, H = 2, 4, 8, 2
x = torch.randn(B, T, D)
qkv = nn.Linear(D, 3*D)(x)
q, k, v = qkv.chunk(3, dim=-1)
def split(z):
    return z.reshape(B, T, H, D//H).transpose(1, 2)
q, k, v = map(split, (q, k, v))
scores = q @ k.transpose(-2, -1) / ((D//H)**0.5)
mask = torch.triu(torch.ones(T, T, dtype=torch.bool), diagonal=1)
weights = scores.masked_fill(mask, float("-inf")).softmax(dim=-1)
z = (weights @ v).transpose(1, 2).contiguous().reshape(B, T, D)
out = nn.Linear(D, D)(z)
assert out.shape == x.shape
assert torch.allclose(weights.sum(dim=-1), torch.ones(B, H, T))
```

<a id="sec-1-1"></a>

### 基础算例：拆头前后的元素对应关系

输入投影形状为 (B,T,8)，两头时每头特征维为 4。先把最后维拆为 (2,4)，再把头轴移到时间轴前，得到 (B,2,T,4)。若直接把内存重排成同形却没有正确 transpose，每个头可能混入不同时间位置。选 B=1、T=2 并给元素依次编号，人工追踪一遍拆分与合并，比仅检查输出 shape 更能发现顺序错误。

<a id="deep-dive-1"></a>

### 深入讲解：逐轴追踪手写多头注意力并验证参数身份

输入(B,T,dmodel)经QKV线性投影，重排为(B,h,T,dh)，其中dmodel=h×dh。Q与K末维点积得(B,h,T,T)，softmax沿最后键轴，乘V后回到(B,h,T,dh)，转置拼接成(B,T,dmodel)。

reshape只重解释布局，transpose才调换轴；先转头轴再合并时需遵守实际内存与元素顺序，不能因为元素总数相同就任意reshape。用每个位置不同的可识别数值，容易发现头与时间被混合。

投影层必须作为模块参数稳定注册，不能每次forward新建随机层，否则优化器未必更新正在使用的对象。dropout在对照时关闭，mask与缩放一致，才能与参考模块比较函数。

前向一致后，还要核对输入与各投影参数梯度。某个参数未参与图或共享关系不同，可能在少数输入上前向近似却反向不一致。参数名称、形状与身份都要对应。

最后做因果行为和padding行为检查，再测数值精度与效率。手写实现的价值是解释全部轴和局部运算，而不是仅获得相同输出shape。

<a id="sec-2"></a>

## 2. 代码中每一步的意义

chunk 拆出三种角色，transpose 改变轴顺序，contiguous 为后续重排提供连续布局。mask 在分数上排除未来，softmax 只沿键轴归一化。输出投影把多个头重新混合。

<a id="sec-2-1"></a>

### 机制展开：对照实现先消除合法差异

手写模块与参考模块应统一参数映射、bias、缩放、mask、精度和 dropout。不同输出投影或权重平均约定会产生合法差异，不应直接归为错误。先比较前向，再用同一个标量目标比较输入和各参数梯度；参数需稳定注册。若只检查一个随机输出标量，可能漏掉头维顺序或未被优化器管理的权重。

<a id="sec-3"></a>

## 3. 对照代码追踪每一个维度

初始每个 token 有八个特征，合并投影得到二十四个，再平均拆成查询、键和值各八个。两头意味着每头四维，转置后批次和头在前两轴，各自独立计算四个查询对四个键的分数。softmax 后每行总和为一，因此输出是该头值向量的加权组合。

随后交换头轴与时间轴，确保同一 token 的两头四维内容放在一起，再重排回八维。若直接 reshape 而不先转置，可能把不同位置内容混合，形状仍是正确的，所以形状检查只是第一步，还需要理解元素顺序。

可把未来位置输入改成很大数，验证更早位置在因果掩码下输出不变；去掉 mask 则通常变化。这个干预比仅打印三角矩阵更直接验证信息边界。正式网络还包含 dropout、输出投影与残差，比较时需固定相应随机性。

参数由线性层注册，临时在每次前向新建 Linear 则不会形成稳定训练模块。学习示例可逐行创建，封装模型时必须放入初始化中保存，避免每步重置权重。

<a id="sec-4"></a>

## 4. 综合算例与实现核对

用最小两位置检查因果性：第一位置只能读取自己，权重应为一与零；第二位置可以在两个值间分配。保持第一位置输入不变，只改第二位置，第一位置输出应在固定参数与关闭随机层时不变。

再把两头设成同样投影，观察它们的权重相同，说明多头结构只是提供不同学习空间，不自动保证多样性。是否学到不同关系，需要实际训练和分析。

封装成类时，把 qkv 和输出投影建立为实例属性，把维度约束在初始化中验证。前向只执行计算，不新建随机权重。这样优化器才能持续更新同一组参数，保存加载也才有确定状态。这是从逐行演示走向训练模块时必须完成的一步。

<a id="sec-5"></a>

## 5. 专题实现：前向与反向同时对照参考模块

逐行演示适合观察形状，研究实现还要核对参数生命周期和梯度。下面把 QKV 与输出投影注册为模块属性，用参考 MultiheadAttention 的参数初始化，使比较针对同一数学函数；关闭 dropout，使用双精度和明确因果 mask。

```python
import copy
import torch
from torch import nn

class ManualAttention(nn.Module):
    def __init__(self, dim, heads):
        super().__init__()
        if dim % heads:
            raise ValueError("dim 必须能被 heads 整除")
        self.dim, self.heads = dim, heads
        self.qkv = nn.Linear(dim, 3 * dim)
        self.projection = nn.Linear(dim, dim)

    def forward(self, x, blocked):
        batch, length, dim = x.shape
        parts = self.qkv(x).chunk(3, dim=-1)
        q, k, v = [z.reshape(batch, length, self.heads, dim // self.heads)
                     .transpose(1, 2) for z in parts]
        scores = q @ k.transpose(-2, -1) / ((dim // self.heads) ** 0.5)
        weights = scores.masked_fill(blocked, float("-inf")).softmax(-1)
        values = (weights @ v).transpose(1, 2).contiguous().reshape(batch, length, dim)
        return self.projection(values)

torch.manual_seed(42)
reference = nn.MultiheadAttention(8, 2, dropout=0., batch_first=True).double()
manual = ManualAttention(8, 2).double()
with torch.no_grad():
    manual.qkv.weight.copy_(reference.in_proj_weight)
    manual.qkv.bias.copy_(reference.in_proj_bias)
    manual.projection.load_state_dict(reference.out_proj.state_dict())
x1 = torch.randn(2, 4, 8, dtype=torch.float64, requires_grad=True)
x2 = x1.detach().clone().requires_grad_(True)
blocked = torch.triu(torch.ones(4, 4, dtype=torch.bool), diagonal=1)
y1 = manual(x1, blocked)
y2, _ = reference(x2, x2, x2, attn_mask=blocked, need_weights=True)
assert torch.allclose(y1, y2, atol=1e-10, rtol=1e-8)
y1.square().sum().backward()
y2.square().sum().backward()
assert torch.allclose(x1.grad, x2.grad, atol=1e-10, rtol=1e-8)
assert torch.allclose(manual.qkv.weight.grad, reference.in_proj_weight.grad,
                      atol=1e-10, rtol=1e-8)
with torch.no_grad():
    altered = x1.detach().clone()
    altered[:, 3] += 10
    assert torch.allclose(manual(altered, blocked)[:, :3], y1.detach()[:, :3])
print("forward, backward and causal boundary passed")
```

前向一致只核对函数值，输入和投影梯度再核对链式法则路径，最后的干预检查因果性。三类检查互补。示例只含因果 mask，加入 padding 时还需额外处理全屏蔽行、批次 mask 广播与参考 API 的布尔约定；不能因本例通过就宣称全部变长场景已覆盖。

<a id="sec-6"></a>

## 6. 进阶：从逐行示例到可训练模块的等价验证

手写实现应与参考模块在共享参数、相同 mask、关闭随机层时对比前向与梯度，不能只核对输出形状。常见差异来自头轴转置、缩放维度、bias、dropout 和掩码方向。

可对未来 token 做干预，验证更早输出不变；也可对一个参数做方向梯度检查。前向一致但梯度不一致可能是 detach 或原地操作。研究中的加速实现还需分别报告数值容差、训练质量与吞吐，避免把近似误差藏在接口一致里。

<a id="sec-6-1"></a>

### 等价实现比较必须包括参数映射与反向

手写多头注意力通常把投影结果从 (B,T,Hd) 拆成 (B,H,T,d)，逐头计算后再合并。reshape 与 transpose 次序不同会改变元素所属头；最终形状正确并不能证明头内数据对应正确。

与参考模块对照时先关闭 dropout，复制对应 Q、K、V 和输出投影参数，固定 mask 与 dtype，再比较前向输出。随后用同一标量损失反传，比较输入梯度及投影参数梯度；只核对某个输出标量可能遗漏参数注册或转置错误。

参数必须在模块初始化时稳定注册，而不是每次 forward 创建新层。后者会重置权重并使优化器状态与实际计算不一致。还要核对 bias、缩放系数、掩码和权重平均约定，否则两个合法但不同的函数不应被要求数值相等。

<a id="sec-7"></a>

## 7. 练习与解析

**题目：** D=10、H=3 时上述 reshape 能直接使用吗？

**解析：** 不能，当前设计要求 D 能被 H 整除。可改变维度或明确使用不同投影设计，不能靠截断偷偷丢掉特征。

<a id="sec-7-1"></a>

### 边界追问：输出一致能否跳过梯度对照

**问题：** 手写注意力前向接近参考实现，是否即可断言所有参数都能正确训练？

**推理解析：** 还需检查参数注册、梯度路径和共享，某些实现可输出正确却未被优化器管理。使用同一标量损失比较输入和全部投影参数梯度，关闭随机性并统一 bias、缩放与 mask。前向、反向与完整训练效果是不同验收层级。
