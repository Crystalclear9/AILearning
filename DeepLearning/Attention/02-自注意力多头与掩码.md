## 1. 自注意力与交叉注意力

自注意力的 Q、K、V 来源于同一序列，使各位置互相交换信息。交叉注意力的查询来自一条序列，键和值来自另一条，例如解码器读取编码器表示。两者的公式可以相同，差别在信息来源。

多头机制把表示投影到多个子空间，分别计算注意力，再拼接并投影回模型维度。不同头可以学习不同关系，但不能预先断言某一头一定表示语法或某种固定功能。

<a id="sec-2"></a>

## 2. 掩码是信息边界

padding mask 排除无效位置；因果 mask 阻止当前位置读取未来 token。通常把禁止的分数设为极小值，使 softmax 权重接近零。若某个查询把所有键都屏蔽，普通 softmax 可能产生无效值，需要避免这种输入或使用有明确定义的实现。

```python
import torch
torch.manual_seed(42)
x = torch.randn(1, 4, 8)
scores = x @ x.transpose(-2, -1) / (8 ** 0.5)
blocked = torch.triu(torch.ones(4, 4, dtype=torch.bool), diagonal=1)
scores = scores.masked_fill(blocked, float("-inf"))
weights = torch.softmax(scores, dim=-1)
output = weights @ x
print(output.shape)  # [1, 4, 8]
print(weights[0, 0]) # 第一位置仅能读取自己
```

这里为了突出运算，直接让 Q、K、V 等于输入；实际模型通常包含可学习投影。

<a id="sec-1-1"></a>

### 基础算例：因果与 padding 掩码作用到不同集合

长度为 3 的有效序列补到 5，位置 2 的因果读取集合只含合法过去与当前位置，不能读位置 3，也不能读末尾两个 padding。因果 mask 限制时间方向，padding mask 排除无效位置，两者都要满足。可把未来 token 改成任意值，检查过去输出是否不变；再改 padding，检查有效输出是否不变。测试应关闭 dropout，否则随机波动会遮蔽可见性错误。

<a id="sec-2-1"></a>

### 机制展开：不同接口的布尔 mask 语义可能相反

有的接口用 True 表示屏蔽，有的表示允许，应按所用函数核对而不是复制熟悉数组。加性 mask 通常在分数上加入零或负无穷，需与 dtype、广播和无效行处理配合。因果边界还会受缓存长度与位置影响。用可见集合和干预验证实际输出，比仅确认矩阵三角形更能证明信息没有从其他路径泄漏。

<a id="deep-dive-2"></a>

### 深入讲解：可见性矩阵怎样规定每个查询允许使用的信息

自注意力QKV来自同一序列，交叉注意力的查询与键值来自不同表示。分数矩阵形状为查询长度×键长度，因此两种长度可以不同，mask也必须按该关系对齐。

因果mask只允许当前位置读取过去及约定的自身位置，padding mask排除不存在内容。两者职责不同，合并时要核对布尔含义和加性负无穷约定；不同接口True含义可能不同，不能凭参数名猜测。

训练整段并行不违背自回归，因为mask切断未来；目标错位另负责预测下一token。若mask存在但标签或打包边界错，仍可能泄漏或优化错误任务。

多头将投影分成多个子空间，各自匹配再拼接输出。固定模型维度时增加头数不一定同比增参数；但头维、内核和表示能力都会变化。

用两个序列仅修改未来token，检查过去输出是否不变，再加padding核对有效位置。这样的行为测试比只打印一个上三角矩阵更能确认实际信息边界。

<a id="sec-3"></a>

## 3. 计算成本与解释边界

普通全注意力需要构造 $T\times T$ 的分数关系，计算和朴素实现的中间存储随序列长度平方增长。优化内核可以减少实际内存访问和显式存储，但不会自动把所有全注意力计算变成线性成本。

设批量 B、头数 h、长度 T、每头维度 d，显式分数张量形状为 $B\times h\times T\times T$，主要乘法量约为 $O(BhT^2d)$。例如 B=1、h=8、T=4096，单份 FP16 分数张量约占 256 MiB，尚未计 softmax、反向缓存与其他激活。长度翻倍时这部分约变四倍。

分块融合的精确注意力可避免将完整分数矩阵常驻显存，利用重算及更好的数据访问降低开销；局部或稀疏注意力则改变可见关系，两者应分开。测量时同时报告输入长度、批量、精度、训练或推理模式、峰值内存与耗时，不能用单一短输入判断所有长度上的效率。

<a id="sec-4"></a>

## 4. 掩码要核对语义而非只看类型

不同库的布尔掩码有时用 True 表示“禁止”，有时用 True 表示“允许”；维度广播规则也可能不同。把一个正确形状的掩码交给错误语义的接口，程序可能运行却完全反转信息边界。应查具体函数文档，并用长度为 3 或 4 的例子打印权重核对。

因果掩码的第一行通常只能看到第一个有效位置，后面的行逐步扩大可见范围。padding 与因果掩码叠加后，要确认每个需要输出的位置至少有合法键。对多头多批量输入，检查掩码是否被正确扩展到各批次与头。

<a id="sec-5"></a>

## 5. 头维度与投影参数

常见实现把模型维度分成多个头，每头在较小空间计算，拼接后再投影。头数增加不代表总模型维度或参数按同样倍数增加，要看每头维度是否相应减小。

多头不自动保证多样性，各头可能冗余。解释时应通过实际分析而非为每个头预设一个语言功能。

设模型维度 d、h 个头、每头维度 d/h，常见 Q/K/V 投影各仍是 d×d，输出投影也是 d×d，因此在这种约定下投影参数主项约 4d²，不随 h 按比例增长。若固定每头维度而增加 h，总维度随之扩大，则是另一种比较。

分头需要正确重排批量、长度、头和通道轴，拼接后恢复原维度；不能靠 reshape 后形状合法就认定语义正确。不同头提供不同子空间的加权读取，但可能冗余，是否学到不同功能需要实际消融及输入对照。

<a id="sec-6"></a>

## 6. 进阶：多头分工与掩码的数学边界

多头在不同可学习子空间计算加权读取，提供表达机会而非保证各头语义独立；头可冗余甚至被其他路径补偿。注意力权重还需乘 V 并经过输出投影，不能直接等于最终特征贡献。

掩码施加于归一化前的允许集合。若某行全为负无穷，标准 softmax 的最大值平移可能产生无效数，需定义空行行为。不同 API 的布尔 True 含义可能相反，必须以小因果例子检查真实输出。

<a id="sec-6-1"></a>

### 掩码是合法信息集合而非单纯数组形状

因果掩码限制位置 t 只读取允许的过去与当前位置，padding 掩码排除并不存在的键。二者处理不同边界，通常需要组合。不同 API 的布尔真值可能表示允许或屏蔽，不能把一个接口的掩码原样复制到另一个接口而不核对文档。

若一整行键都被屏蔽，普通负无穷分数的 Softmax 没有常规概率解释，某些实现会产生 NaN 或特殊处理。应在数据与模型接口上避免无合法键，或明确采用空行行为，不应在最后把 NaN 统一置零掩盖前提问题。

可做因果干预检查：固定前 t 个 token，只改变未来输入，比较前 t 个位置输出是否保持一致。这个检查验证可见性路径，比只看掩码是否下三角更强；但还要排除其他跨位置操作或错误缓存把未来信息引入。

<a id="sec-7"></a>

## 7. 练习与参考答案

**练习：** 高注意力权重能否直接证明某个词对最终预测有因果作用？

**答案：** 不能。后续层、值向量与残差路径共同影响输出；可通过干预、遮挡与对照实验补充分析，而非仅把权重图当成完整解释。

<a id="sec-7-1"></a>

### 边界追问：所有键被屏蔽时应该输出什么

**问题：** 某查询对应的分数全被设为负无穷，softmax 是否自然得到全零概率？

**推理解析：** 普通公式分母无有效质量，可能产生无定义或实现特定行为，不应默认全零。应避免无合法键或明确空行协议，并按接口检查数值。最后统一把 NaN 置零会掩盖可见性与数据前提错误，无法证明函数正确。
