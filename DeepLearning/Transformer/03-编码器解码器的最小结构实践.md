## 1. 编码器接口

编码器可在完整输入内双向交换信息，输出每位置上下文表示。分类可以聚合有效位置，序列标注保留逐位置输出。需要位置编码和 padding mask；仅堆一层官方模块并不自动拥有所有任务组件。

```python
import torch
from torch import nn
torch.manual_seed(42)
embedding = nn.Embedding(30, 16)
position = nn.Embedding(10, 16)
layer = nn.TransformerEncoderLayer(16, 4, dim_feedforward=32,
                                   dropout=0., batch_first=True)
encoder = nn.TransformerEncoder(layer, num_layers=2)
tokens = torch.tensor([[2, 5, 6, 0], [3, 8, 0, 0]])
valid = tokens != 0
x = embedding(tokens) + position(torch.arange(tokens.shape[1]))
hidden = encoder(x, src_key_padding_mask=~valid)
pooled = (hidden * valid.unsqueeze(-1)).sum(1) / valid.sum(1, keepdim=True)
assert pooled.shape == (2, 16)
```

## 2. 解码器的额外边界

自回归生成需因果 mask，encoder-decoder 还需交叉注意力与输入 padding mask。不同接口的布尔含义应查官方文档，用小例子确认可见范围，不能只复制另一个函数的 mask。

<a id="sec-1-1"></a>

### 基础算例：编码器与解码器的可见矩阵不同

源长度 3、目标长度 4 时，编码器自注意力矩阵为 3×3，目标自注意力为 4×4 且有因果限制，交叉注意力为 4×3。最后一个维度表示可读取键数，不必等于查询长度。源 padding 影响编码与交叉读取，目标 padding 影响自注意力及损失。分别列出这三种矩阵能识别把源 mask 当目标 mask 使用的错误，不能只用一个通用方阵替代。

<a id="sec-2-1"></a>

### 机制展开：解码器有三种需要分别检查的接口

目标自注意力需要因果与目标 padding，交叉注意力读取编码器输出并使用源 padding，前馈只在每个目标位置变换特征。某些实现还采用不同归一化次序。先画各子层查询、键、值来自哪里，再映射 API 参数；仅凭层名相同复制 mask，容易把源长度和目标长度混用而产生隐蔽错误。

<a id="deep-dive-2"></a>

### 深入讲解：编码器与解码器的接口如何规定信息进入路径

编码器输入嵌入与位置后经过多个块，输出每个源位置的表示。padding mask保证无效源位置不被读取，最终池化或分类头又规定如何将序列变成任务结果。

解码器自注意力只看目标前缀，交叉注意力Q来自当前目标状态，K/V来自编码输出。源mask与目标因果mask形状和含义不同，不能把一张T×T矩阵到处复用。

训练目标右移要与起始结束符一致。若解码输入直接包含当前位置真值且允许读取，网络可能学会复制目标，损失很低但推理失败；这是信息泄漏，不是模型突然泛化差。

维度检查列出批量、源长度、目标长度、模型宽度与头维。交叉注意力分数为目标长度×源长度，不能默认源目标等长。用两者明显不同的小例更容易发现错误。

验证先核对源padding不影响有效结果、未来目标修改不影响过去输出，再比较参考实现前反向。接口边界成立后，完整任务表现才有解释意义。

<a id="sec-3"></a>

## 3. 编码器例子的完整计算链

整数 token 先查词嵌入，位置索引查位置向量，两者相加形成带顺序信息的输入。两层编码器让有效位置互相交换内容，padding mask 屏蔽键端填充。最后把无效位置输出乘零再求和，并除以每条真实长度，得到每样本十六维摘要。

注意 padding 位置输出本身可能非零，因为它可以作为查询读取有效键，所以池化仍需显式排除。只屏蔽键端与只屏蔽输出解决不同问题。全为空的序列会导致分母零与全屏蔽行，应在输入契约中拒绝或另定义处理。

这个编码器没有训练标签与任务头，当前输出仅验证计算接口，不能声称已经拥有语义分类能力。接入分类头后仍需完整损失、优化与独立评价。解码器则要增加因果限制，不能直接把编码器输出当下一词生成器。

练习可交换两个有效 token，比较加入位置前后的行为；或改变填充长度，检查有效摘要是否保持合理一致。通过这些小干预理解结构，比只记模块名字更扎实。

<a id="sec-4"></a>

## 4. 综合算例与实现核对

对第二条只有两个有效 token 的输入，平均分母为二而非四。若直接对全部位置 mean，摘要会随 padding 长度变化，模型可能利用无关长度模式。对全空输入，应预先定义行为，不依靠除零后再补数。

可改变 token 的位置索引、互换顺序和增加尾部 padding，分别验证位置作用与掩码作用。前两者可能合理改变表示，单纯增加无效尾部在合适实现下不应改变有效聚合的任务含义。

这个例子使用可学习绝对位置，长度不能超出位置表范围。支持更长序列需要相应设计与训练验证，不能只把数组尺寸调大就宣称已获得可靠长上下文能力。

<a id="sec-5"></a>

## 5. 进阶：编码器摘要的padding依赖反例

键端 padding mask 防止有效查询读取无效键，不一定把无效查询输出置零；因此全序列直接平均仍会混入填充。正确摘要需按有效位置加权，并处理全空序列，两个 mask 所处阶段不同。

检验可给同一有效序列添加不同长度填充，在固定参数、评估模式和相同位置规则下比较摘要。若变化，先查归约与掩码，再查数值实现。位置表长度扩展也只是接口改变，不能作为长度泛化的证据。

<a id="sec-5-1"></a>

### 最小结构实验应先验证三个边界

第一是形状边界：输入嵌入维、注意力头数与前馈输入必须兼容；第二是可见性边界：目标自注意力不能读取未来，交叉注意力只读取合法源位置；第三是损失边界：padding 与不应监督的 token 不进入有效分母。

可用一个源长度 3、目标长度 4 的人工样本，列出每个目标位置能看到的键集合。只改变未来目标 token，过去 logits 应保持一致；只改变被屏蔽源 padding，其余有效输出不应受影响。测试在评估模式关闭随机性后进行。

模块可运行并不等于完整模型已学会任务。先让极小数据集过拟合，再增加样本和长度，观察训练、验证与生成。模型结构、标签错位、掩码和优化问题应分别定位，避免用增加层数补偿数据接口错误。

<a id="sec-6"></a>

## 6. 练习与解析

**题目：** padding 位置不参与平均池化，是否还需要在注意力里屏蔽？

**解析：** 需要。否则有效位置已在注意力阶段读取填充表示，最后排除填充输出不能消除这种影响。

<a id="sec-6-1"></a>

### 边界追问：源目标长度相同能否共用所有 mask

**问题：** 一个例子里源长与目标长恰好相同，通用方阵能否证明编码解码接口正确？

**推理解析：** 不能，巧合尺寸会隐藏角色混淆。使用不同源目标长度，分别核对编码自注意力、目标因果自注意力和交叉读取，再测试 padding 与标签错位。测试应破坏巧合而非只验证容易通过的同形输入。
