## 1. 训练时把目标错开一位

对 token 序列 $x_1,\dots,x_T$，自回归模型分解为 $p(x)=\prod_tp(x_t\mid x_{<t})$。输入前 $T-1$ 个 token，标签是后 $T-1$ 个 token，用因果 mask 保证每个位置只读取允许的前缀。

训练时真实前缀已知，因此多个位置的损失可并行计算；生成时后续 token 尚未知，需要逐步产生。这个区别解释了 Transformer 训练能并行处理序列，而自回归生成仍包含串行步骤。

<a id="sec-1-1"></a>

### 基础算例：下一 token 训练的两种长度

序列含 BOS、A、B、EOS，输入取 BOS、A、B，标签取 A、B、EOS，三个位置可并行计算条件损失，但各位置只能看到因果允许的前缀。生成时 A 尚未知道，需要先预测它再接回，因而通常逐步进行。训练并行不违反自回归分解。缓存保存已有键值以减少重复计算，却必须保持位置编号和会话前缀一致，否则形状合法也会读取错误历史。

<a id="deep-dive-1"></a>

### 深入讲解：并行训练与逐token生成如何表达同一概率分解

序列概率按前缀分解，训练输入前T−1个位置、目标后T−1个位置，因果mask禁止看到未来。并行计算各位置损失，并不允许当前预测读取其真实下一token；标签错位和mask是两个都要正确的条件。

模型给下一位置logits后，可贪心、采样或多候选搜索。温度和top-p改变采样分布，输出质量、长度和多样性随之变化。比较时固定解码与停止规则，不挑一次幸运回答。

KV cache保存历史键值以免每步重算历史表示，新的查询仍要读取已有缓存。位置索引必须延续历史，mask也需适配查询长度1与键长度增长；每步重置位置会改变函数。

prefill处理长提示，decode逐步新增，计算形态不同。吞吐、首token延迟、后续延迟和缓存内存应分别测；参数量不能解释所有并发和长上下文成本。

关闭随机层后比较整段与逐步缓存同位置输出，是强接口验证。随后再检查EOS、padding、批内不同长度及文档边界，避免仅单条短输入通过就认定生成正确。

<a id="sec-2"></a>

## 2. logits 如何变成输出

贪心解码每次取最大概率，随机采样保留多样性。温度 $\tau$ 通过 $\operatorname{softmax}(z/\tau)$ 改变分布尖锐程度；top-k 只保留最大若干候选，top-p 保留累计概率达到阈值的候选集合。采样设置会影响重复、随机性和可靠性，但不能凭低温消除事实错误。

<a id="sec-2-1"></a>

### 机制展开：采样温度改变分布而非只改随机种子

logits 除以温度 τ 再归一，τ 较小使概率更集中，top-k 或 top-p 又改变候选支持。贪心取最大不是从原分布采样。选择解码规则会改变长度、多样性和错误形态，因此模型比较需固定提示与生成预算。较低温度不能保证事实正确，参考 likelihood 也不能直接替代实际生成的任务评价。

<a id="sec-3"></a>

## 3. KV cache 为什么有用

因果生成时，已有 token 的键和值可以缓存，新一步只计算新 token 的相关表示并读取历史缓存，避免每步重复计算完整前缀。缓存随层数、长度、键值头数、维度和精度增加，占用可观内存。

缓存减少重复工作，但新查询仍需要读取历史键值；长上下文并不是免费。训练时通常没有同样的逐步生成需求，也不能机械沿用推理缓存的管理方式。

<a id="sec-4"></a>

## 4. 训练损失与实际生成质量

训练提供真实前缀，推理逐步使用自身输出；一个早期错误可能改变后续上下文。因此验证负对数似然是重要信号，却不能代替完整生成评估。应查看重复、提前结束、任务约束遵守和事实支持等维度。

批量生成时，不同样本结束时间可能不同，需要正确处理结束符、padding 和位置索引。KV cache 也要与各样本的有效长度对应，不能简单把所有历史都当作同样长度。性能优化应先确认与无缓存实现的输出在同一设置下相符，再测量速度与内存。

<a id="sec-5"></a>

## 5. 训练标签与特殊符号

起始、结束与填充符号必须与 tokenizer 和损失配置一致。结束符让模型学习何时停止，padding 通常不参与损失；若忘记屏蔽，大量填充会主导训练。

打包多文档到一个序列时，还应明确文档间是否允许注意，位置如何重置。样本拼接提高利用率，却可能改变训练条件，需与目标定义一致。

<a id="sec-6"></a>

## 6. 进阶：自回归似然与并行训练的条件

链式分解 $p(x)=\prod_tp(x_t\mid x_{<t})$ 对任意联合分布成立，因果 mask 使模型实现该条件结构。训练已知真实序列，可同时计算多个条件损失；生成未知未来，仍有串行依赖。二者并不矛盾。

KV cache 的等价复用还要求历史位置在相同上下文规则下表示不变，位置索引、滑窗和缓存截断需一致。改变前缀、位置或模型状态后不能无条件沿用旧缓存。缓存验收应对照无缓存 logits。

<a id="sec-6-1"></a>

### 训练并行与生成串行来自条件分解

给定真实前缀，因果掩码允许在一次前向中计算多个位置的下一 token 损失；生成时下一个输入尚未确定，通常需要逐步采样。训练矩阵化并没有消除自回归依赖，只是已知标签让各条件项能并行计算。

KV cache 保存已有位置的键和值，新查询只需与历史缓存交互。缓存减少重复前向计算，却占用随层数、序列长度和 KV 头数增长的内存。缓存必须与模型、输入前缀、位置和 mask 一致；不同会话不能无条件共享。

温度缩放、top-k 和 top-p 改变实际采样分布。贪心不是从原分布随机抽样，较低温度也不保证事实正确。评价时固定提示、生成预算、停止规则和采样协议，才能区分模型变化与解码变化造成的差异。

<a id="sec-7"></a>

## 7. 练习与参考答案

**练习：** 对序列 `[A,B,C,D]`，下一词训练的输入和标签各是什么？为什么每个位置可以同时计算损失？

**答案：** 输入为 `[A,B,C]`，标签为 `[B,C,D]`。真实前缀已提供，因果 mask 阻止读取后续输入位置，所有位置的合法条件概率可在一次前向中求出。

<a id="sec-7-1"></a>

### 边界追问：缓存能否不看前缀在会话间复用

**问题：** 两次请求长度相同、模型相同，可否直接沿用旧 KV cache？

**推理解析：** 不行，缓存依赖实际前缀、位置、mask 和模型状态。形状相同不代表内容与语义匹配。合法共享需满足相应前缀与实现条件；否则生成会读取其他历史。测缓存加速时还应区分命中策略与完整冷启动成本。
