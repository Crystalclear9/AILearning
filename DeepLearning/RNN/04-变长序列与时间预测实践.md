## 1. 对齐批量

变长序列可填充后配真实长度，也可使用打包。摘要必须从真实最后位置或有效掩码聚合得到。填充值即使为零，经过带偏置状态更新也可能改变结果，因此不能假定自动无影响。

```python
import torch
from torch import nn
from torch.nn.utils.rnn import pack_padded_sequence
torch.manual_seed(42)
x = torch.randn(2, 5, 3)
lengths = torch.tensor([5, 2])
packed = pack_padded_sequence(x, lengths, batch_first=True, enforce_sorted=False)
model = nn.GRU(3, 4, batch_first=True)
_, final = model(packed)
print(final.shape)
assert final.shape == (1, 2, 4)
```

## 2. 时间划分与滑窗

训练窗口和标签窗口可能重叠，相邻随机划分容易泄漏。按时间向前验证，必要时留间隔。归一化只在训练历史拟合，未来目标不能出现在滚动特征中。

<a id="sec-1-1"></a>

### 基础算例：滑窗重叠为何不能随意随机分割

原序列长度 6，窗口 (1,2,3) 预测 4，窗口 (2,3,4) 预测 5，共享大量原始观察。若随机分到训练与测试，测试附近的信息可能已进入训练，不等于面对未来。先按时间确定预测边界，再生成允许窗口，并处理标签窗是否跨边界。归一化只用合法训练历史；测试时能利用此前真实已观察历史，但不能利用同一测试期尚未发生的未来值。

<a id="sec-2-1"></a>

### 机制展开：时间切分后再确定滑窗可用历史

预测未来的样本由截止时点以前输入和之后标签组成，划分需防标签窗跨越不允许边界。测试早期可使用已真实观察的训练期历史，不必机械清空；但测试未来不能回填较早样本。标准化与补值状态也只在相应训练期拟合。多步递归预测还需区分后续输入用真实值还是自身预测，两者评价任务不同。

<a id="deep-dive-2"></a>

### 深入讲解：滑动样本怎样同时遵守时间边界和变长接口

用过去L步预测未来H步，样本锚点t决定输入[t−L,t)与目标[t,t+H)。训练验证按时间隔离时，窗口重叠可能让同一原始片段跨集合，需根据部署协议处理边界和间隔，而非先造全部窗口后随机拆行。

标准化只用训练可见数据拟合，未来已知协变量与未来未知目标分开。节假日可预知，未来销量不可拿来充下一步输入；这一点决定实验是否真实。

批量对齐需保存每条真实长度，loss和聚合排除padding。只取张量最后位置可能读到填充；双向网络还要符合任务允许的未来可见性。

递归预测不断反馈自身结果，误差会改变后续条件；直接多步输出有不同损失权重和表达。分别报告各horizon和时间段，不用平均一步误差替代整个预测范围。

与最后值、季节复制和简单线性基线比较，并记录窗口、重训频率和有效样本单位。大量重叠窗口并不提供同等数量独立证据，区间与重采样需保留时序结构。

<a id="sec-3"></a>

## 3. 基线与多步评价

先比较最后值、季节性复制或简单线性基线，再用复杂序列模型。分别报告不同预测跨度与时间区间；递归预测的误差会积累，直接预测多个未来值则有不同输出与损失设计。

在滚动预测中，多个起点的标签区间可能重叠，评价不能把这些误差当成完全独立重复。先固定预测起点、跨度与可见历史，按时间区间汇总，分别比较每个 horizon 的 MAE/RMSE 与简单基线。窗口标准化与特征拟合也只能使用起点以前允许的信息。

递归预测每步把自身预测反馈，训练时低一步误差并不能保证远期稳定；直接多步输出则需要明确各跨度权重。季节性复制基线在强周期数据上可能很强，若复杂模型只在少数波动区间改善，应报告分段效果而不是仅给总体平均。

<a id="sec-4"></a>

## 4. 打包示例到底忽略了什么

第二条输入虽然张量里有五步，但真实长度为二，打包只让前两步进入该样本的循环更新。最终状态因此对应真实末尾，而不是三步填充后的状态。enforce_sorted=False 让接口处理长度顺序，但长度仍必须与样本一一对应。

若手工排序，应同时重排输入、标签和长度，输出后按需要恢复原顺序。很多序列错误来自只排序其中一项，张量形状仍完全正确。验证时用不同长度且内容容易区分的样本核对。

时间预测还需区分一条长流与独立序列。跨块保留隐藏状态时保持实体对应，并在合适边界切图；随机打乱窗口却保留上一批状态，会把无关历史串起来。状态生命周期必须成为训练设计的一部分。

<a id="sec-5"></a>

## 5. 综合算例与实现核对

在打包代码中，把第二条第三到第五步改成任意大值，真实长度仍是二，最终状态应保持不变。这个干预验证这些位置确实被忽略。若不打包直接跑完整五步，通常会变化。

时间预测可设置最后观测值作为基线。如果序列网络只在随机切分优于它，在未来时段却失败，应先检查窗口共享、时间漂移与泄漏，而不是只调整隐藏维度。

多实体序列还要按实体独立维护状态。不同用户窗口拼批后，不能把上批第一个用户的状态传给下批另一个用户。状态归属和生命周期属于数据接口，与网络公式同样重要。

<a id="sec-6"></a>

## 6. 进阶：变长打包与时间验证的双重边界

打包避免填充参与状态更新，损失掩码则避免填充参与目标，二者不能互相替代。按长度排序时输入、标签和实体状态要同步，并在输出需要时恢复顺序。有效长度错误通常不表现为维度异常。

滑窗时间预测还要考虑相邻窗口共享观察和目标跨度。随机窗口划分可能高估新时段能力，必要时留间隔以避免标签窗口重叠。归一化、状态和特征都只能使用相应训练历史。

<a id="sec-6-1"></a>

### 时间预测中的滑窗不能跨越信息边界

对长度 L 的历史预测下一步，样本可写为 $x_{t-L:t}\to y_t$。相邻窗口高度重叠，随机拆分窗口可能让测试时点附近的同一原始片段进入训练，无法模拟真正未来预测。应先按原时间确定训练、验证和测试边界，再构造允许的窗口。

多步预测分直接输出多个步长与递归把预测接回两种方式。递归会累积自身误差，直接方法则增加输出建模需求；比较时按每个预测跨度报告误差，不能只汇总一个平均掩盖远期退化。

变长序列中的 padding 只是批量存储手段，不应改变真实序列结果。打包、长度排序和恢复顺序需要一起核对。若按批排列后标签没有同步重排，训练仍会运行却学到错误配对。简单的最近值或季节性基线有助判断复杂序列模型是否带来真实收益。

<a id="sec-7"></a>

## 7. 练习与解析

**题目：** 每小时数据用过去 24 小时预测下一小时，随机划分相邻窗口为什么可能乐观？

**解析：** 窗口共享大量观测且可能混入未来时段，评估更接近记忆相似窗口。应模拟真实向未来预测，并核对标签与观察边界。

<a id="sec-8-2"></a>

### 边界追问：补齐序列后取最后位置总正确吗

**问题：** 短序列 padding 到统一长度，直接取输出最后一帧作为真实末状态是否可靠？

**推理解析：** 不一定，最后位置可能已处理 padding，或双向状态含不同语义。应使用真实长度、合适打包或显式索引，并恢复排序对应。用两条长度不同的序列逐项核对，防止形状正确却读取了无效尾部。

<a id="sec-8"></a>

## 8. 进阶研究练习与解析

**问题：** 证明传递隐藏状态但 detach 的截断 BPTT，与完整序列反向不等价。

**解析：** 后块损失依赖边界状态，而状态又依赖前块参数；完整链式法则包含这条路径。detach 将该导数置零，前向数值不变但梯度项丢失。截断是计算与偏差折中，不是无损省显存。

**实现验收：** 在短确定序列与双精度小 RNN 上比较两种梯度，分别增加截断跨度。确认序列归属、reset 和损失权重一致，避免把数据排序错误混为截断效应。

<a id="sec-8-1"></a>

### 综合练习：状态跨批传递与反传边界

**问题：** 连续序列分两批读取，如何区分保留状态与保留完整计算图？

**逐步解析与验收：** 保留隐藏值可继续利用历史；对其 detach 会切断跨批梯度，属于截断反传。新序列开始应按定义重置，批顺序改变时要保持状态与实体配对。验收用两条不同序列跟踪隐藏状态，证明没有把前一个实体的记忆传给另一个。
