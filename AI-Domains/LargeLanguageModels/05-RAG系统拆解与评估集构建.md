## 1. 文档处理

保留标题层级、段落、表格及来源版本，按语义切块。块太小可能缺上下文，太大降低检索粒度并占窗口；重叠能缓解边界，也会引入重复。用真实问题验证，不凭固定字数认定最佳。

一个可审查的块至少应保留文档 ID、版本、章节路径、原始位置与内容。切块后抽查跨段定义、表头与表格行、前置条件和否定句是否被分离；必要时将标题路径或短上下文附在检索块中，但避免把无关整章塞进每块。文档更新和删除应同步到索引，保留稳定来源定位以支持引用。

在固定问题集上比较切块方案时，先检查答案证据是否完整落在候选块中，再检查检索能否取回，最后检查生成是否正确使用。三步分别定位切分、召回和回答错误。记录块大小分布、重叠、候选数、重排与总上下文预算，才能判断改进来自何处。

<a id="sec-2"></a>

## 2. 检索与重排

关键词适合精确术语编号，向量适合部分语义相似，混合与重排可互补。召回先保证证据进入候选，再检查重排是否保留与生成上下文是否截断。每阶段记录候选与得分便于诊断。

<a id="sec-2-1"></a>

### 机制展开：重排解决候选排序而非全部检索问题

召回集合含证据才有重排机会；若证据未索引或未召回，再强交互模型也无法恢复。切分重叠增加覆盖也带来重复候选，可能挤占上下文。可分别比较召回候选、重排前后和最终上下文支持，记录 k、token 预算与延迟。多证据问题还需评价联合充分性，单个相关段落命中不一定足够回答。

<a id="sec-3"></a>

## 3. 构建评价集

包含事实查询、多段组合、数字比较、答案不存在、冲突版本和长干扰。每题标注支持段落与可接受答案规则，按文档来源隔离开发测试。检索 Recall@k、回答正确、证据支持与引用分别统计。

<a id="sec-1-1"></a>

### 基础算例：检索的候选库覆盖决定召回上限

一百个问题中二十个答案根本不在当前库，若把全部失败都计为召回器错误，就混淆库覆盖与检索能力。可分别报告可回答比例，以及可回答集合中的 recall@k；最终系统仍需面对不可回答问题并正确拒答。相关证据标注还要允许多个充分段落，固定库版本、权限与查询集合，使不同实验的分母一致。

<a id="deep-dive-3"></a>

### 深入讲解：RAG评价集怎样把回答正确与证据使用分开

先收集真实问题并标注可接受答案、必要证据和来源版本。问题应覆盖单块、多块、表格、时间更新及不可答，不能只用容易检索的标题问句代表所有任务。

切块保留标题路径、文档ID、原始位置和版本。块太小丢条件，太大降低粒度并占窗口；重叠引重复，需在固定问题上比较证据完整和召回，而非凭固定字数断言最佳。

检索Recall@K要有明确正例集合和库规模，重排再看证据是否留在预算内。答案正确但依据错误可能是记忆或猜测，引用正确却答案歪曲也不算成功，二者分别测。

延迟拆检索、重排、生成与工具等待，同时看端到端尾部；缓存键应与影响结果的配置和知识版本关联，文档删除更新需避免旧证据继续返回。

错误表回到原问题和证据，区分切块、检索、理解、生成和评价歧义。数据集与规则先固定，再选方案并保留新独立问题，才能防止系统只修复已知题目。

<a id="sec-4"></a>

## 4. 工具与成本

工具调用记录输入、输出、失败与重试，不能把执行成功当成用户任务成功。报告延迟、token、检索成本和缓存行为。缓存应关联文档版本，避免持续返回旧证据。

将一次请求拆为检索、重排、生成与工具等待，记录各阶段耗时和失败状态，再报告端到端中位及尾部延迟。工具返回结构合法，只代表接口调用成功；应继续核对目标字段是否满足用户任务，以及失败重试是否重复产生副作用。

缓存键应包含影响结果的提示、检索配置、模型和知识版本等条件，更新文档后使相关旧缓存失效。比较方案时固定问题集，统计成功回答成本与失败重试成本；仅计算单次理想调用的 token 费用，会低估真实使用开销。

<a id="sec-5"></a>

## 5. 用失败台账改进系统

每个错误题记录问题、期望证据、召回候选、重排结果、最终上下文与回答，便于定位。若证据从未进入候选，优先改检索；证据在上下文却未被用，检查组织与生成；引用错误则检查来源绑定。

块切分可利用标题与段落，表格需保留表头和行关系。机械按字符切断条件或单位，会使检索段看似相关却无法支持答案。文档更新时删除或失效旧块，并使缓存关联版本，避免混用新旧内容。

评价集按文档家族与时间隔离，包含答案不存在和冲突版本，才能检查是否会编造。最后同时报告检索、答案、证据支持与成本，让改进位置有依据，而不是只看一个综合分数。

<a id="sec-6"></a>

## 6. 进阶：检索评估的候选与可回答性

Recall@k 需定义所有可支持答案的证据集合，多段组合题不能只标单个段落。切块大小改变候选数量和相关性，评价应考虑等上下文预算，而非只固定 k 就视为成本相同。

测试集包含无答案、过时版本与冲突证据，才能区分真实使用证据和语言猜测。缓存关联文档版本，保存检索中间产物与逐项错误标签。改进应针对故障阶段并在独立文档上确认，而不是反复调同一小题集。

<a id="sec-6-1"></a>

### 检索评价的分母是候选全集与可回答集合

recall@k 需要明确“相关文档”的标注和候选库版本。若索引中根本没有答案，召回失败与库覆盖不足应分开；若标注只含一个证据，而另一个段落同样充分，也可能低估有效召回。评价集应保留证据、答案与不可回答原因。

切分大小改变段落完整性与检索粒度，重叠能保留跨边界信息，却增加重复候选和索引成本。重排只在已召回集合中选择，无法找回完全漏掉的证据。比较时固定库、查询、权限和预算，分别检查召回、重排与生成。

最终回答评估包括正确性、证据支持、引用精确性、无法回答识别和延迟成本。按问题来源或模板去重分组，避免开发时见过同题变体。失败台账应指向可验证阶段，而不是把所有错误归为“幻觉”后统一更换提示。

<a id="sec-7"></a>

## 7. 练习与解析

**题目：** 正确证据进入候选但最后答案错，应优先扩大向量库吗？

**解析：** 不一定。先检查重排、上下文组织、截断和生成使用证据的过程；扩大库可能增加干扰而无助修复当前瓶颈。

<a id="sec-8-2"></a>

### 边界追问：召回率高是否就足够回答多证据问题

**问题：** 候选命中一段相关文字，但答案需另一段联合信息，recall 指标高是否保证最终正确？

**推理解析：** 不保证，标注应区分相关、充分与联合证据，候选和上下文预算还可能丢掉关键部分。库覆盖、召回、重排与生成各设诊断。不可回答问题也应纳入，固定库版本和查询来源，避免指标分母与真实任务不一致。

<a id="sec-8"></a>

## 8. 进阶研究练习与解析

**问题：** 给出 RAG 的分阶段评价设计，避免把生成能力和检索错误混淆。

**解析：** 为问题标注支持证据和可接受答案，先测召回与重排保留，再向生成器提供相同金标准证据，分开观察理解与使用证据。最终链路评价同时记录答案、支持和引用；无答案与冲突版本必须纳入。

**研究延伸：** 在相同上下文 token 预算下比较切块与 k，而不是仅固定候选数。记录索引版本、缓存和失败台账，改进在独立文档测试。正确证据已提供却答错时，扩大向量库并不是有依据的首选。

<a id="sec-8-1"></a>

### 综合练习：将 RAG 错误定位到可验证阶段

**问题：** 一组回答错误，如何判断改召回还是改生成？

**逐步解析与验收：** 先检查库覆盖和证据进入上下文的路径，再用理想证据作诊断对照：理想证据仍失败则研究生成，真实检索漏证据则研究相应检索阶段。验收另检查引用是否支持结论与不可回答识别，不能将所有失败统一归因于提示不足。
