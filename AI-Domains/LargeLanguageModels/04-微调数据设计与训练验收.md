## 1. 样本覆盖

为目标任务包含常规、边界、歧义、格式错误与证据不足情况。大量重复模板可能只教会措辞；来自同一文档的多个问答应按来源分组划分，避免验证只是内容记忆。

训练数据需明确角色、特殊符号、损失位置、截断与长度。监督标签若与实际希望行为冲突，再好的优化也只能更忠实拟合错误目标。

<a id="sec-1-1"></a>

### 基础算例：样本条数不等于有效监督量

一百条回答各十个有效 token，与十条各一千 token，分别提供约一千和一万监督位置。按 token 平均与按样本等权会给不同训练贡献。提示、padding 和被截断尾部是否纳入损失，也改变目标。记录有效 token 与任务来源比例，检查目标回答是否完整，比只报告“微调了多少条”更能解释训练行为和能力偏向。

<a id="deep-dive-1"></a>

### 深入讲解：微调样本怎样从数量转向覆盖和有效监督

一条样本包含输入任务、条件信息、目标回答和loss位置。大量模板改写可能只教固定措辞，需覆盖长度、边界、不确定、异常格式和任务变化。样本生成方便不等于监督正确。

按原文档、事件或模板来源隔离训练验证，防止同源问答跨集。抽查事实、数字、角色和起止符，尤其截断后目标是否仍由可见输入支持；缺上下文却保留确定答案会教错误行为。

选择全量或低秩、目标层和冻结策略，应由任务与预算验证。参数少仍可能过拟合，更多训练也可能损害原能力；记录学习率、有效token和检查点选择。

格式用解析器及字段约束，事实用证据，拒答同时测该回答与该保留不确定的案例。把各维度分开，避免长回答和礼貌风格掩盖目标失败。

保存底座、tokenizer、模板与适配配置，独立加载核对固定样本。微调结果不是一份孤立适配权重，而是可恢复的模型与输入协议。

<a id="sec-2"></a>

## 2. 选择微调范围

全量微调、LoRA、量化底座上的适配具有不同资源和可训练范围。LoRA 的秩、目标模块、缩放和学习率相互影响，应先建立小范围可复现基线。可训练参数少不代表激活与底座内存消失。

<a id="sec-2-1"></a>

### 机制展开：微调范围应从待改变能力倒推

全量、部分层、适配器与低秩方案限制的参数空间不同。若目标是补可更新事实，检索可能更易维护；若是稳定格式或特定任务行为，微调可研究，但仍需固定数据与评价。低损失可能只代表模板记忆。分别测目标能力、保留能力、错误与成本，避免把一种廉价适配在小开发集的成功推广成所有任务通用结论。

<a id="sec-3"></a>

## 3. 验收维度

检查目标任务正确率、格式遵循、校准或拒答、旧任务回归、长度与成本。保存训练配置、底座版本、tokenizer 与适配权重。只保存适配器而不知道对应底座，交付无法可靠恢复。

把验收写成固定集合与判定规则：格式任务用解析器及字段约束检查，问答任务按事实和证据评分，拒答任务同时包含应该回答与不应断言的样例。原能力回归应使用独立任务，防止仅在目标格式变好时漏掉其他能力退化。

结果表同时列底座、微调版本、主要指标、长度、延迟与失败类型，并按相同解码设置比较。保存完整加载说明：底座及 tokenizer 的版本、适配目标层和缩放、特殊 token 与提示模板、精度和检查点选择规则。另起进程加载产物后，用固定样本核对输出与评价过程，确认交付可以恢复。

<a id="sec-4"></a>

## 4. 训练样本截断会改变任务

若长指令占满窗口而回答被截掉，样本几乎没有目标监督；若关键约束在被截的尾部，模型看到的任务与标签不匹配。应统计有效回答 token、截断比例和长度分布，不只统计样本条数。

LoRA 的目标模块影响可调整的功能空间。只适配部分投影与适配全部层并不等价，秩增加也不必然改善泛化。按训练预算、任务指标和旧能力回归选择，不根据可训练参数比例直接推断效果。

偏好数据还可能偏向更长或更肯定的回答。验收应包含证据不足、冲突与需要简洁输出的任务，避免把评价者风格偏好误当真实性。保存底座、tokenizer、模板和适配器的完整版本关系。

<a id="sec-5"></a>

## 5. 进阶：微调目标的有效token与选择效应

同样样本数可能包含完全不同有效回答 token。截断指令尾部、回答为空或把用户文本误计为目标，会改变实际训练任务。需记录损失掩码、长度分布和有效监督量，再比较方法。

适配器与底座、模板、tokenizer 版本必须绑定。领域验证提升可能来自重复来源，应按文档或任务族隔离。偏好数据的长答偏置和评价器偏好也要通过控制长度、盲评与回归任务检查，不能只凭训练损失证明改进。

<a id="sec-5-1"></a>

### 微调样本的有效监督区域决定学到什么

对包含系统提示、用户输入和回答的样本，常只对规定回答 token 计损失；若把全部提示都纳入，会改变目标与有效权重。padding、截断与多轮拼接还可能删除本来应监督的结尾，或把不可见信息放进输入。

长样本若按 token 平均，会贡献更多监督位置；按每样本平均则给长短样本不同相对权重。重复模板、少数高频来源和低质量长回答可能主导优化，需统计有效 token、任务类别与来源占比，而不只报告样本条数。

验证应覆盖目标能力、保留能力、事实、格式和拒答边界。训练 loss 下降可能只是模板拟合，不能独立证明任务改善。先固定未参与构造与选择的评价集，再比较全量微调、部分参数与低秩方案，同时报告成本和退化。

<a id="sec-6"></a>

## 6. 练习与解析

**题目：** 领域知识每天更新，是否应每天把全部文档微调进参数？

**解析：** 先明确需求。若主要是查询更新事实，检索与版本化文档可能更直接；微调适合稳定行为与格式等目标，也可与检索结合，需比较成本和可靠性。

<a id="sec-6-1"></a>

### 边界追问：训练 loss 低是否证明微调能力覆盖

**问题：** 数据模板非常重复，loss 很低，但新措辞任务失败，应该怎样解释？

**推理解析：** 可能主要拟合模板，需检查任务多样性、来源、有效 token 与截断。独立评价包括新表达、保留能力和关键边界，再比较不同训练范围及成本。训练样本条数不等于有效监督或覆盖，不能以一个优化数字替代能力验收。
