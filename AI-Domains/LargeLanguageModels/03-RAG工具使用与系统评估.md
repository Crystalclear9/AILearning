## 1. RAG 的完整链路

检索增强生成通常先切分文档并建立索引，再把用户问题转换成查询，召回候选、必要时重排，最后把证据交给生成模型。每个环节都可能失败：切块割裂语义、检索未命中、重排丢失答案、模型忽略证据或引用不支持结论。

向量检索按表示相似度找候选，关键词检索更擅长精确术语、编号等，混合检索可互补。切块大小、重叠与元数据应按文档结构设计，并保留来源和版本，便于核查。

<a id="sec-1-1"></a>

### 基础算例：证据缺失与证据忽略分开诊断

回答某文档问题失败，先检查正确证据是否在库、是否进入召回、是否经过重排保留、是否被拼入上下文。若真实证据不在最终上下文，先改检索链；若给人工确认的理想证据仍失败，再研究生成。这个对照用于定位，不是可部署的额外信息。引用还需逐条支持结论，不能因为输出附链接就视为已证实。

<a id="deep-dive-1"></a>

### 深入讲解：RAG和工具系统的成功需要每一段接口都成立

文档处理生成带来源块，查询检索候选，重排选择证据，组装上下文后生成并定位引用。正确答案可能在原库却不在块中，在块中却未召回，已召回却被重排丢弃，或已在上下文却答错，修复位置不同。

因此分别测证据可得、召回、重排和答案支持。最终流畅度不能反推检索成功；一个引用存在也不说明它支持该主张，需核对具体片段和版本。

工具调用还包含参数、执行、结果解释与任务完成。接口返回成功只表示动作按接口完成，未必满足用户目标；失败重试和重复副作用需由任务协议管理。

检索文档属于待分析数据，不能自动升级为指令。缺证据、冲突和无关要求应有专门测试，防止为完成格式而编造来源。

评价集固定问题、证据和判断规则，包含可答、不可答、多文档及冲突案例。将错误沿链路定位，比只换更大生成模型更能形成有效研究与迭代。

<a id="sec-2"></a>

## 2. 检索与回答分别评价

检索可报告 Recall@k，检查正确证据是否进入候选；回答要检查正确性、完整性、证据支持与引用准确性。只看最终回答难以知道问题发生在哪一层。测试集应包含可回答、证据不足、文档冲突和版本更新等情况。

模型调用工具时，工具返回的是数据，需要明确结构、权限和错误处理。工具执行成功不代表任务结论正确；仍要验证输出是否满足原始需求。

<a id="sec-2-1"></a>

### 机制展开：检索与生成需要分项条件评价

先测可回答问题的证据是否进入候选及上下文，再测给定真实上下文时回答是否正确与有支持。理想证据对照用于诊断上限，不是系统部署能力。召回 k 增大可能覆盖更多证据，也增加干扰和成本，重排无法找回未召回内容。评价库版本、权限、切分和证据标注固定后，才可解释某个组件改动带来的收益。

<a id="sec-3"></a>

## 3. 控制事实与行为错误

提示应明确目标、必要上下文、输出格式和判断标准，并用代表性样例评估。文档中的文字不应自动成为系统指令，检索内容可能包含无关要求。证据不足时，应表达缺失信息，而不是为了完成格式生成没有来源的结论。

将回答要求拆为可分别检查的约束：事实主张是否有输入证据、引用是否指向支持该主张的片段、格式能否解析、工具动作是否完成目标。引用存在但内容不支持，仍属于事实错误；工具返回成功但结果不满足任务，仍属于任务失败。

构造证据缺失、来源冲突和检索文本含无关要求的测试，分别检查模型是否说明缺失、依据版本处理冲突并保持任务边界。对“证据在上下文却答错”与“正确证据根本未召回”采用不同修复；提升提示不能补出不存在的事实，增加检索也不自动修复输出约束。

<a id="sec-4"></a>

## 4. 用故障分类改进RAG

可以把失败分成“没有检索到证据”“证据被截断或排列不当”“读到证据但答错”“答案正确但引用错误”。每类有不同改进：召回策略、切块与重排、提示与模型、引用绑定。没有故障分类就盲目换大模型，可能增加成本却不解决主要问题。

文档更新后，索引和缓存也要反映版本。回答时保留来源标识与有效日期，能够检查是否引用过时内容。测试集应包含答案不存在的提问，确认系统能识别证据不足，而不是从相似段落拼出看似合理却没有支持的说法。

<a id="sec-5"></a>

## 5. 检索内容与指令边界

外部文档是待解释证据，不应自动获得改变任务或调用工具的权限。系统应保留用户意图与工具边界，对文档中无关命令按数据处理。

生成引用也需核对来源是否真正支持该句，而非仅输出看似有效的链接。证据缺失、冲突或过时都应在结果中明确反映。

输入可在结构上区分任务指令、用户问题与引用文档，并保留来源定位；文档中的“忽略前文”等文字属于待分析数据，不能仅因被检索到就提升为操作指令。对需要执行的工具，实际动作还应受工具参数和任务范围约束，而非只靠提示词声明。

构造同时含正确证据和无关指令的文档，检查回答是否引用有效事实、是否执行无关动作；再加入纯粹缺证据和冲突来源对照，区分边界失败与检索失败。一个措辞模板通过几条例子不构成普遍保证，应使用固定测试与持续回归。

<a id="sec-6"></a>

## 6. 进阶：RAG错误的因果链与来源绑定

最终正确依赖证据存在、召回、重排、上下文组织和生成使用，任一环可失败。只看答案分数无法定位瓶颈；正确段落已召回时，扩大索引未必改善，还可能增加干扰。

引用存在不等于支持该句，需核对论断与证据的实际蕴含。工具执行成功也不等于用户任务成功。外部文档应作为数据而非指令，证据不足、版本冲突与权限边界均需在系统协议中明确。

<a id="sec-6-1"></a>

### RAG 应分解检索失败与回答失败

系统链路包括文档解析、切分、表示、召回、重排、上下文拼接和生成。答案错误可能因为证据未被索引、未召回、被重排丢弃、截断或生成阶段忽略。只看最终正确率无法定位应改检索还是模型。

可先用人工确认的证据构造“理想上下文”对照：若仍回答错误，重点检查理解与生成；若理想上下文正确而真实检索失败，则分析召回和候选集合。理想证据对照不是上线可得输入，而是诊断工具，报告时应明确。

检索文本是外部数据，不因进入上下文就成为可信系统指令。文档权限、来源、引用绑定和无法回答规则都属于系统设计。回答附引用也不代表引用确实支持结论，应逐项检查支持关系、版本与可访问性。

<a id="sec-7"></a>

## 7. 练习与参考答案

**练习：** RAG 回答错误，但正确段落已出现在召回前五名，应优先继续提高 Recall@5 吗？

**答案：** 不一定。需检查重排、上下文截断、证据格式、问题歧义及生成阶段是否正确使用证据。已有召回不是整条链路成功的充分条件。

<a id="sec-7-1"></a>

### 边界追问：带引用是否就等于有证据支持

**问题：** 回答末尾附了正确文档链接，但句子数字不在该文档中，算忠实回答吗？

**推理解析：** 不算，仅链接存在未证明逐项支持。需要核对事实与来源段落、版本、权限及可回答性。检索内容也不是更高优先级指令。将召回、上下文与生成分别评价，可定位缺证据还是证据被误用，避免所有问题只靠改提示。
