## 1. 图文相似度矩阵

一个批次 N 个图像向量与 N 个文本向量归一化后，形成 $N\times N$ 相似度矩阵，对角线是原配对。分别按图找文和按文找图计算交叉熵，可构成对称目标。存在多个合法配对时，对角唯一正例可能引入假负例。

```python
import torch
import torch.nn.functional as F
torch.manual_seed(42)
image = F.normalize(torch.randn(4, 8), dim=-1)
text = F.normalize(torch.randn(4, 8), dim=-1)
scores = image @ text.T / 0.1
target = torch.arange(4)
loss = (F.cross_entropy(scores, target) +
        F.cross_entropy(scores.T, target)) / 2
print(loss.item())
assert torch.isfinite(loss)
```

本例随机特征仅展示目标计算，没有训练出对齐能力。温度与批量负例都会影响优化，不能跨设置直接比较损失值。

<a id="deep-dive-1"></a>

### 深入讲解：图文矩阵目标与生成桥接各学习什么

批量B对图文产生B×B相似度，常以对角为匹配，行列分别交叉熵。若同一内容有多个正例，对角one-hot目标可能过窄，需要明确多正例处理；重复候选也改变有效难度。

对比目标优化检索几何，不直接教模型逐token生成。要连接生成模型，需投影或查询模块把模态特征变成可读取表示，再以序列目标训练；冻结与解冻策略影响适应和成本。

跨注意力的Q来自生成或融合状态，KV来自另一模态，长度未必相等。必须核对空间、时间及padding mask，防止坐标位置与语义配对错位。

分阶段训练可能先对齐再做指令任务，每阶段数据和损失有不同角色。只报告最终模型参数量，不能说明额外预训练和教师信息的影响。

验收先在小矩阵手算双向loss，再检查模态特征是否真影响输出。配对检索、条件生成与下游任务应分开报告，不能将一个指标当作全部跨模态能力。

<a id="sec-2"></a>

## 2. 融合与生成

双编码器便于预计算检索，跨编码器或交叉注意力能更细致交互但成本更高。视觉语言生成常先对齐视觉表示与语言空间，再用指令数据训练任务行为；冻结范围与训练阶段依具体方法。

<a id="sec-1-1"></a>

### 基础算例：双塔召回与交互重排的成本分工

有一百万候选文本时，双塔可预计算文本表示，查询图像只计算一次表示并检索；跨注意力交互模型若对所有候选逐个联合计算，成本通常不同。常见组合是先召回少量候选，再重排，但第一阶段漏掉的证据无法由重排找回。比较时同时固定候选规模和预算，分别报告召回、重排质量与端到端延迟。

<a id="sec-2-1"></a>

### 机制展开：交互融合与独立编码保留不同计算

独立编码便于预计算候选，交互注意力能在查询条件下细读另一模态，却常需逐候选联合计算。可用双塔召回再交互重排，但评价需同时包含第一阶段漏检。训练阶段还要明确冻结与可学习参数、监督区域及有效 token，避免同名多模态模型其实使用不同数据与更新目标。

<a id="sec-3"></a>

## 3. 对比矩阵的两个归一化方向

按行交叉熵时，每张图在四条文本中找对应项；按列方向则每条文本在四张图中找对应项。两个方向共享相似度但分母不同，平均可让双方都学匹配。随机特征的对角未必较大，损失只是可计算，不代表语义已对齐。

归一化向量使点积成为余弦相似度，温度控制候选分布尖锐度。若温度太小，少数负例可能主导梯度；太大又使区分平缓。训练目标和批量组成都影响结果，不能用同一损失阈值跨模型判断好坏。

双编码器可提前索引文档或图像，查询便宜；跨注意力需对候选联合计算，通常更细但更贵。实际系统常先召回再重排，应分别评价两阶段，而非把成本和质量全归一层。

<a id="sec-4"></a>

## 4. 综合算例与实现核对

设两张图和两段文本的相似度矩阵为第一行三与一、第二行零与二。按行时，对角正确项都大于其他项，图找文较容易；按列时第一图对第一文、第二图对第二文仍最好，但候选差距不同，所以两方向损失未必相同。

现在把两段文本设为完全同义，仍强迫只认对角，会把另一条合理描述惩罚为负例。这个算例帮助判断目标标签是否符合真实语义，而不只是矩阵维度对不对。

进一步练习是把对角配对索引随机打乱，观察训练目标与真实语义相反。数值损失仍可优化，因此配对质量是模型正确性的前提。正式评价应保留多个正例规则、候选库和模态预处理，形成可重复协议。

<a id="sec-5"></a>

## 5. 进阶：对称对比损失与多正例扩展

图找文按相似度矩阵行归一化，文找图按列归一化，两个方向的候选分布不同，损失通常不相等。若一图多描述，唯一对角标签会把其他合法项作为负例，需要相应多正例或数据规则。

归一化向量的点积是余弦，温度控制尖锐度，不可跨温度直接比损失。双编码器便于离线索引，联合编码更细但更贵，召回加重排系统应分别评价准确与成本，而不是用一个综合结果混淆阶段贡献。

<a id="sec-5-1"></a>

### 对称对比损失的两个方向归一化不同

相似度矩阵 S 的行 softmax 表示每张图在文本候选中选择，列 softmax 表示每段文本在图像候选中选择。即使使用同一矩阵，两个分母不同，不能只计算一次行损失就称为完整对称目标。对角线为正例还要求 batch 配对顺序正确。

可用 2×2 人工矩阵手算两方向概率，故意交换两条文本，观察标签是否同步变化。样本索引错配时形状与损失都可正常运行，训练却在拉近错误对象。归一化、温度和批采样也应在对照中保持一致。

跨注意力融合与独立双塔检索具有不同计算代价：双塔可预计算候选表示，交互模型需要更细粒度联合计算。可先召回再重排，但整体召回率受第一阶段候选限制。研究比较同时报告检索质量、候选规模与推理成本。

<a id="sec-6"></a>

## 6. 练习与解析

**题目：** 正确描述不只一条，仍只用对角标签有何问题？

**解析：** 合理描述可能被当作负例拉远。可改正例定义、去重或采用多正例目标，并在评价中允许多个合法匹配。

<a id="sec-6-1"></a>

### 边界追问：双塔检索好能否直接证明生成好

**问题：** 图文表示检索准确，接入语言模型是否无需再训练或评价就能细致回答？

**推理解析：** 不能，解码器还需理解连接接口与细粒度信息，投影或交叉注意力等训练目标影响结果。检索、融合和生成是不同能力。固定输入与证据做分项对照，并报告冻结范围和监督区域，不能用一个对齐分数覆盖完整系统。
