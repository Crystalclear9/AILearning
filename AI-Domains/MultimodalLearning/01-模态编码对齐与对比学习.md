## 1. 为什么需要多个模态

同一事件可由图像、文本、声音等不同信号描述。多模态学习希望利用互补信息，例如视频中的声音帮助判断动作，图像帮助理解文本所指对象。模态之间也可能冲突或缺失，不能默认多输入必然提高效果。

每种模态通常有专门编码器，输出特征后再对齐或融合。输入单位不同：图像是 patch，文本是 token，音频可能是波形帧或时频特征，因此长度、时间和空间关系都需要处理。

<a id="sec-2"></a>

## 2. 对比学习形成共享空间

图文双编码器分别生成图像和文本向量，归一化后用点积表示相似度。对一批配对数据，让正确配对的得分高于错误配对，常使用带温度参数的交叉熵式对比目标。

例如同一张猫图与“猫在窗边”是正对，批内其他描述作为候选负对。但其他描述也可能真实描述这张图，形成假负例；批量构造和配对质量会影响学习。

<a id="sec-1-1"></a>

### 基础算例：配对分类从相似度矩阵逐行归一

两张图、两段文本的相似度矩阵可设为 [[2,0],[0,2]]。按行 softmax，每张图选正确文本的概率约为 0.881；按列处理则评价每段文本选图。若交换文本顺序而不改正例索引，程序形状不变却训练错误配对。温度、归一化与候选采样都影响目标，先核对索引对应再解释学习效果。

<a id="sec-2-1"></a>

### 机制展开：对比目标的负例分母随批次变化

每个图像与配对文本为正例，分母含当前候选文本，反向亦然。增大批次改变负例数量，也改变难例和假负例组成，并非只减少梯度噪声。若多条文本均正确却只认对角正例，就会相互排斥。归一化与温度控制相似度尺度，应固定配对标识和采样规则后研究 batch 收益。

<a id="deep-dive-2"></a>

### 深入讲解：共享表示为何取决于配对机制而非模态数量

图像与文本编码到共享空间，训练希望正确配对比其他候选更相似。批量相似度矩阵每行回答图像找哪段文本，每列回答文本找哪张图；双向损失的归一轴和正例定义需清楚。

一个图可有多个正确描述，若将它们当负例，训练信号会冲突。跨来源错误配对、字幕错位和同事件重复，也可能让模型学到背景或模板而非内容联系。

单位归一和温度改变相似度尺度，softmax分数是相对候选概率，不自动校准为真实类别概率。零样本分类由类别文本描述构造候选，模板与候选集合改变任务。

模态互补需靠任务证明。若只看文字就能答对，加入图片后的高分不能说明读图；通过单模态、置换和需视觉证据的问题区分信息来源。

评价检索、分类和生成各有指标，冻结表示与微调又不同。共享空间有用性需要独立下游和来源外数据，而不只是对比训练loss低。

<a id="sec-3"></a>

## 3. 零样本分类的含义

把候选类别写成文本描述，编码后与图像比较相似度，可构造零样本分类。这里“零样本”通常指没有使用目标任务的标注训练，并不代表模型完全没见过相似概念或图像。提示模板和类别描述会影响结果，应固定协议比较。

例如为三种动物写文本描述，分别编码并归一后，与同一图像表示计算相似度，最大者作为分类。类别描述、提示模板和候选类别集合共同决定任务；增加相似类别会改变决策难度，不能用较小候选集合的高分声称在完整分类体系同样可靠。

温度化 softmax 可将相似度转为相对候选分数，但未经校准不等于真实类别概率。选择模板和温度应使用开发集，并固定后再测试。还要检查预训练与评价数据的重叠风险，将没有目标标注微调、没有见过目标概念和严格未见数据区分开。

<a id="sec-4"></a>

## 4. 检索方向改变评价问题

给图找文本与给文本找图不一定同样困难。一张图可能对应多个合理描述，一段描述也可能适用于多张图，因此 Recall@k 的正例集合需要预先定义。只把原始配对当唯一真值，可能把语义正确的结果误计为错误。

对比学习中的相似度温度控制分布尖锐度，批量负例数量也影响优化。评价时应固定候选库、去重规则与类别分布，避免候选集合变简单后分数上升被误认为表示能力提高。共享向量空间是工具，仍需具体任务验证。

<a id="sec-5"></a>

## 5. 数据配对有噪声

图片旁的文本不一定描述图片，视频字幕也可能谈未出现对象。弱配对大数据提供规模，却带来噪声和偏差。应抽查配对质量、重复和时间同步，不能假定文件名相同就语义对应。

共享向量空间由训练目标塑造，图像与文本相似度是模型定义的匹配，不等于所有语义关系都可由一个点积表达。

<a id="sec-6"></a>

## 6. 进阶：对比目标的概率分类解释

批内 InfoNCE 类目标把配对识别为候选分类，温度和负例分布共同决定梯度。它可在特定采样与假设下联系互信息下界，但不能由损失下降直接宣称所有语义信息增加。

假负例、重复图文和配对噪声会改变监督含义。零样本分类通常指未用目标任务标注微调，不代表预训练从未见过相似概念。评价应明确候选库、多个正例和提示模板，而非只给一个检索分数。

<a id="sec-6-1"></a>

### 对比学习把跨模态配对变成分类问题

图像编码 u 与文本编码 v 经归一化后，用相似度除以温度 τ 得 logits。一个 batch 内，图像 i 将其配对文本作为正类，其余文本作为候选负类；反向再用文本检索图像，常取两个方向损失平均。温度改变概率集中程度，也改变梯度尺度。

若 batch 中存在多个语义等价文本，把其余匹配项全当负类会引入假负例。去重、多正例目标或采样策略会改变训练信号，不能只用更大 batch 数量推断有效负例更多。配对错误则可能让模型学习来源或模板捷径。

零样本分类依赖文本提示为类别构造表示，不代表完全没有任务先验；提示模板、类别词和编码协议都影响结果。评估时固定这些选择，并与单模态基线比较，避免把文本模板调优收益全部归于跨模态对齐。

<a id="sec-7"></a>

## 7. 练习与参考答案

**练习：** 一批数据中有两张同款商品照片，为什么把其中另一张对应描述当作严格负例可能有问题？

**答案：** 描述可能同样适用，目标却强迫模型把语义正确的配对拉远。可考虑多正例、去重或更精细的配对规则。

<a id="sec-7-1"></a>

### 边界追问：批次越大负例越多是否总改善

**问题：** 图文 batch 含多个同义正配对，却把非对角项全作负例，会发生什么？

**推理解析：** 假负例可能让本应接近的语义互相排斥。更大批次改变难度与组成，不只是减少方差。可研究多正例目标、去重或采样，并固定温度和候选规则。先验证配对标识，再把检索或分类改善解释为对齐收益。
