## 1. 先建立稀疏基线

TF-IDF 加线性分类器或关键词检索能以低成本提供强基线。训练词表、IDF 与分类器都需在训练流程内拟合。长文本需决定截断、分段或聚合方式，并按文档分组避免段落泄漏。

<a id="sec-1-1"></a>

### 基础算例：训练词表与测试未知词的分工

训练语料只有“红苹果”“绿苹果”，词表应从训练文本建立；测试出现“蓝梨”时，依据预先规定的未知词规则编码，不能为了让测试更方便临时扩词并重新拟合全部表示。TF-IDF 的 IDF 也来自训练文档频次。对照稀疏与上下文模型时，固定划分、截断与评价，才能区分表示差异和额外输入信息带来的收益。

<a id="sec-2"></a>

## 2. 最小可运行文本分类

```python
from sklearn.pipeline import make_pipeline
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
texts = ["good useful book", "great helpful guide", "excellent useful notes",
         "bad useless book", "awful confusing guide", "poor useless notes"]
y = [1, 1, 1, 0, 0, 0]
model = make_pipeline(TfidfVectorizer(), LogisticRegression(C=10))
model.fit(texts, y)
print(model.predict(["useful guide", "useless book"]))
```

这只是展示接口，样本太少不能证明泛化。正式实验需独立划分、多个来源与恰当指标。英文默认分词规则不能无修改地视作中文分词方案。

<a id="sec-2-1"></a>

### 机制展开：最小示例先验证流水线再研究泛化

文本分类代码应让训练词表、向量化与模型的 fit 范围一致，验证和测试只 transform、predict。内置小语料可以检查标签配对与接口，但样本量太少不足以给稳定方法排名。扩大实验前先确认重复、来源和长度截断；比较复杂模型时保持相同目标与开发预算，避免把输入信息更多误认为架构本身更强。

<a id="sec-3"></a>

## 3. 序列标注与结构

实体识别同时关注边界与类型。BIO 标签要检查非法转移，CRF 等结构方法可表达相邻约束，但其作用取决于任务与模型。评价以完整实体为单位，与大量 O 标签的逐 token 准确率区别很大。

例如“北京大学”真实标注为一个 ORG，预测为“北京”的 LOC，即使多数非实体 token 都正确，实体级评估仍应计一次错误预测和一次漏掉的真实实体。需明确采用严格边界且类型一致的匹配，还是另行报告部分重叠；主指标不能混合两种口径。

子词分词还需要定义标签对齐：只在首个子词计算损失，或向后续子词传播标签，是不同协议；padding 和特殊 token 应屏蔽。BIO 中 I-ORG 紧跟 O 等情况可通过受约束解码处理，但约束应同时适用于训练与评价解释。CRF 学习相邻标签得分不代表自动解决跨句实体、一词多义或长程指代。

<a id="deep-dive-3"></a>

### 深入讲解：把稀疏分类检索和结构标注落实到不同接口

文本分类基线先用训练语料建词表与TF-IDF，再拟合线性模型；Pipeline保证每折重新拟合。若先对全数据向量化或筛词，验证已提供信息。未知词、空文本和类顺序也是输入输出契约。

检索将查询与候选打分，需要候选库、正例集合和排名指标。随机少量负例与全库困难检索不同，Recall@K须对应同一库规模；近重复可能让看似语义能力其实是词面记忆。

标注则从token表示输出BIO等标签，子词与原词对应要明确，padding不参与损失。只给首子词标签与向全部子词传播是不同协议，训练和评估映射应一致。

结构化解码可限制某些非法标签转移，但不能自动解决跨句指代和未见实体。解码前后分别检查跨度与类型，避免用后处理掩盖标注定义不清。

先用极小人工样例逐项核对向量化、预测和还原，再做真实验证。分类、检索、标注共享表示技术，却不能共用未经说明的评价分母。

<a id="sec-4"></a>

## 4. 示例中词频如何产生预测

向量器从训练文本建立词表，每篇转成稀疏加权向量；分类器把各词权重线性组合为得分。useful 与 useless 在训练标签中相反，所以新短句仍可利用这些词。它没有自动理解否定和复杂语义，只学习当前特征下的统计关联。

可加入“not useful”作为挑战，检查 unigram 是否混淆，再用双词 n-gram 对照。若仍用极少样本，不应把改善当普遍证据，应该扩充独立样本并比较同一评价协议。这体现从失败例子形成假设再验证的流程。

实体识别中，一个边界多一词可能使整个实体判错，即使大部分 token 正确。报告实体级 precision 与 recall，并给出边界错、类型错和遗漏的分类，才能指导改进。

<a id="sec-5"></a>

## 5. 综合算例与实现核对

给示例新增“not good”负类和“not bad”正类，先只用单词，再加入双词组合，比较模型能否表达局部否定。词袋不是无法处理所有否定，而是单词独立计数缺乏顺序，n-gram 增加了有限局部信息。

在正式数据上，还要避免某类独有文件头、作者名或模板成为捷径。可以按作者或来源划分，删除与任务无关的元数据后对照，查看成绩变化。文本内容与采集痕迹都可能被模型利用。

验收应包括未知词、新来源、长文本和空文本等输入。空文本被转换成全零特征时，分类器仍可能输出先验偏置；这不是有依据的语义判断。接口应明确是否允许空内容，评估中也要记录其比例。

<a id="sec-6"></a>

## 6. 进阶：稀疏基线与上下文模型的比较

线性词袋模型提供可解释、低成本的统计基线，n-gram 增加有限顺序信息。上下文模型的优势应在相同来源划分和预算说明下验证，而非与弱默认配置比较。预训练数据污染还可能影响基准结论。

文本长度、作者、模板和来源常产生捷径，按文档或事件分组比随机段落更接近新内容泛化。解释词权重反映模型依赖，不意味着词本身因果决定类别，相关措辞和采集机制都可能影响。

<a id="sec-6-1"></a>

### 稀疏基线的价值在于提供可诊断对照

文本分类可将训练文档拟合为 TF-IDF，再接线性分类器，并把两者放入同一交叉验证流程。验证文档只能使用训练词表与权重。若先对全体文本拟合词表或筛词，即使没有显式用测试标签，也改变了未见输入边界。

比较上下文模型时，应固定划分、标签、主要指标和开发预算。若稀疏模型在长文本上表现稳定，而复杂模型因截断丢失末尾证据，差异来自输入覆盖，不能简单归因于表示能力。错误分析可按长度、词频、否定、实体和来源分组。

序列标注进一步需要检查 token—标签对齐，子词拆分时决定哪些位置参与损失，预测后再映回原跨度。输入与标签形状相同并不能证明语义对齐。可用一条含标点与未知词的短句手工追踪全部位置，作为独立检查。

<a id="sec-7"></a>

## 7. 练习与解析

**题目：** 一篇长文切成十段后随机分到训练测试，有何风险？

**解析：** 同文主题、措辞与内容重复可能泄漏。若目标是新文档泛化，应先按文档划分，再在各部分内部切段。

<a id="sec-7-1"></a>

### 边界追问：上下文模型更差是否必然表示能力不足

**问题：** 稀疏模型能用全文，神经模型把关键末尾截掉，结果差能否归于架构？

**推理解析：** 不能，输入覆盖不同是竞争解释。统一或明确截断策略、预算与划分，再按长度和证据位置分析。强基线有诊断价值；复杂模型训练成功也不保证目标信息进入输入。先核对可见证据，再讨论上下文表示收益。
